## 二、架构分析讨论与组织

### 2.1 本周期组织的关键设计前讨论

1. **招商证券内存竞价分片数据一致性与跨集群同步（LDP）**
   - **关键点**：UF30 综合/竞价共用一个数据库的存量模式，与上线内存竞价分片后的"物理库 + 内存库分离"模式如何兼容；SIS 与 SES 跨集群数据同步路径。
   - **难点**：内存"小核心"定位与客户希望"内存统一查询入口"的诉求冲突；原内存对接推送平台方案因数据同步场景梳理不全已搁置。
   - **结论**：吕益波制定技术方案上升经纪架构办决策；同步推进跨集群同步场景梳理，决策"推送平台 vs 终态 MC3.0"。

2. **南方基金沪深 L1 行情 IOPV 指标计算（LDP / HDF2.0）**
   - **关键点**：单机房内多路行情汇聚排序方案合理性与产品定位。
   - **难点**：当前方案技术可行、性能预计达成验收，但**不具备优势**，且方案在技术平台与资管技术部分实现割裂、产品定位不清晰。
   - **结论**：进入产品决策 + 跨部门技术方案评审。

3. **HDF2.0 引入 RCM 旁路模式支持行情强一致分发（HQ5.5）**
   - **关键点**：行情穿透性能实测必须满足 DFX <20ms 要求。
   - **难点**：上周期识别出主备切换数据丢失、旁路 50ms 阻塞、单线程性能 3 项不满足；本周期与 LDP 架构沟通 RCM 优化版本。
   - **结论**：已申请 RCM 联调版本，验证优化后穿透性能**符合 <20ms 预期**；提交 RCM 优化需求 202605114024，锁定版本计划。

4. **LDP 监控降噪特性（LDP）**
   - **关键点**：方正现场反映监控指标刷屏导致运维降效；SEE 当前不提供公司级降噪方案，APM 集成开源 + Prometheus 改造影响面过大。
   - **结论**：基于 SEE 监视器二开，按"节点 + 指标类型"与"集群 + 指标类型"两维度归并；监控指标分类参考行业标准《金融信息基础设施运行指标体系》。

5. **CRES packv4 兼容性问题（LDP）**
   - **关键点**：t2sdk 24 年 7 月前后 AddField 宽度生效行为不一致，导致 string >255 字节被截断、界面乱码。
   - **结论**：cres 侧实现复杂，**LDP 平台对该场景特殊处理**（Width 固定传 10M），同时向业务部门发风险预警避免同类问题。

6. **数据网格 redo 过半特性（LDP）**
   - **关键点**：主从模式下从节点 redo 积压会导致备节点数据落后；网格 redo 过半引入新的"长期落后单备节点"风险，对读写分离原有行为影响需评估。
   - **结论**：rcm 模块开启 redo 过半时，网格与非网格均需支持读写分离；单备/读分区节点长期落后情况增加监控告警与应急处置。

7. **合规异常交易源端多节点算子动态编排（数据处理平台）**
   - **关键点**：异常交易场景源端节点数不固定，需要算子在采集转换链路上动态编排。
   - **结论**：任务管理初始化支持传入资源加载后处理方法，由业务动态注入数据集合算子资源；下周推动落地与联调。

8. **事件驱动算子从事务模式切换串行执行模式（数据处理平台）**
   - **关键点**：原事务模式并发控制复杂、稳定性差。
   - **结论**：变更为串行模式，每批次必须等上一批次完成后触发；上线后监控延迟表现。

9. **公共组件本周期 10 场设计前讨论密集召开**，覆盖：
   - **安全漏洞修复方向**：axios 1.7.0 升级、Nginx 1.30.1 统一升级（CVE-2026-42945 等）、Redis 7.2 升级。
   - **信创适配方向**：GMU 视频回溯海光 X86、HSIAR 麒麟信安、操作员中心/调度平台 MySQL 8.4 适配。
   - **架构能力建设方向**：RPC 转换工具（适配器模式 + 配置驱动，支持 Dubbo/Spring Cloud/gRPC 互转）、HSCache 本地 + 分布式双层缓存（Caffeine + Redis）。
   - **兼容性专项**：hui-plugin-wss 新老版本兼容（版本号检测 + 特性嗅测 + 老版本降级轮询）、sm2 动态加密 html=true/邮箱/常规三场景拆分。

10. **AIGC 智能设计助手资源修改方式技术路线（低码）**
    - **关键点**：MCP 方式与直接操作底层文件方式的选择。
    - **结论**：MCP 方式新增/修改资源会造成上下文膨胀，**采用直接操作文件方案**；需为所有资源编写 Skill + 校验规则，并抽象生成器接口规范。

  - **低码 0%**：本周期 2 场架构讨论（AIGC 助手资源修改方式、生成器 Skill 内容）均在设计后进行；同一需求（202604214232）上周期已 100% 设计前覆盖，属同一需求的演进讨论。
- HQ5.5 / LDP / 数据处理平台 / SEE 均 100% 维持。

- 按根因看，本周期缺陷集中在四类：
  1. **对外接口/配置/字段命名在提测后调整**（HDF BDATA-2511、2516 等）。
  2. **边界条件与多实例场景覆盖不足**（HDF CSV 解析、多同步算子列序、低码多组织 ID 资产共存、多子 BC 关联同孙 BC）。

  4. **安全规范与权限设计不到位**（公共组件操作员中心越权访问）。

### 6.2 典型设计缺陷与架构侧反思

1. **缺陷**：HQ5.5 / DS 程序在 Nasdaq 流量从 100Mbps 升到 300Mbps 时处理线程积压导致 OOM
   - **根因**：交易所峰值要求 1G，原设计基于成本考虑准出峰值设为 100M，DFX 规格识别不准确。
   - **架构侧反思**：交易场景未识别"遵循交易所 1G 峰值"的 DFX 要求。
   - **改进**：美股业务针对峰值流量进行程序性能优化；梳理美、港股同类问题形成改进计划。并将此案例增加到案例库。

2. **缺陷**：HQ5.5 / UHQ 适配器读取实时行情文件中间状态字段
   - **根因**：文件行情读取字段时无法判别字段是否已更新完成。
   - **架构侧反思**：设计前讨论不充分，缺失"只有文件行情源场景"应对方案；未推进流式行情源替换文件行情源的版本收编。
   - **改进**：补充文件行情字段级数据准确性校验设计；推进版本收编计划。

3. **缺陷**：HDF / 提测后算子名/配置项/字段名多次调整（BDATA-2511、2516 等）
   - **根因**：设计阶段命名规范不严，实现过程中调整。
   - **架构侧反思**：架构侧应在概设评审时即冻结对外接口名称。
   - **改进**：概设模板增加"对外接口名称冻结确认"项。

4. **缺陷**：HDF / 事件对齐算子 AI 生成代码冗余处理（BDATA-2522）
   - **根因**：AI 生成代码未经充分人工优化和精简。
   - **架构侧反思**：AI 辅助编码后需增加人工代码评审环节。
   - **改进**：制定 AI 生成代码人工评审 checklist，重点关注冗余逻辑和性能。

5. **缺陷**：HDF / 多同步算子转发数据列顺序问题（BDATA-2543）
   - **根因**：转发数据集规格基于目标表列顺序而非输入数据集列顺序。
   - **架构侧反思**：数据转发能力对"列顺序基准"的约定不明确。
   - **改进**：制定数据转发列顺序规范：统一以输入数据集列顺序为准。

6. **缺陷**：HDF / Jackson 序列化在不同三方包环境下行为不一致（BDATA-2529）
   - **根因**：Jackson 版本受外部三方包环境影响。
   - **架构侧反思**：框架级基础依赖版本固化与序列化参数固化在设计阶段重视不足。
   - **改进**：固化 Jackson 序列化参数，避免受外部环境影响。

7. **缺陷**：低码 / 物料中心离线导入带 groupId 资产自动声明丢 groupId
   - **根因**：未考虑"同一编码不同组织 ID 资产共存"边界场景。
   - **架构侧反思**：设计前讨论对边界条件覆盖不足。
   - **改进**：增加多实例场景时序图校验、状态机设计的组织 ID 维度检查。

8. **缺陷**：低码 / POJO 多主键序列化报错
   - **根因**：Jackson 不看代码意图只看方法签名，废弃 getPkValue() 被当作 getter 处理。
   - **架构侧反思**：设计评审对"有废弃方法的 POJO 类"序列化行为分析不足。
   - **改进**：设计评审增加 POJO 序列化风险检查；规范明确业务方法需避免 getter 签名模式。

9. **缺陷**：公共组件 / 操作员中心越权访问（202605204538）
   - **根因**：接口设计时未充分进行权限验证设计。
   - **架构侧反思**：安全设计 review 不充分，缺少安全 Checklist。
   - **改进**：建立接口安全设计规范，所有接口设计必须进行安全评审。

10. **缺陷**：LDP / 网格核心存在未启动核心时 todb 节点启动自动退出
    - **根因**：multiproc 核心仅创建自己的上下文，回库获取未启动上下文 ID 失败触发自动退出。
    - **架构侧反思**：设计已识别该场景，但**周边子系统测试场景遗漏**。
    - **改进**：详设和测试分析方案加强评审，尤其是异常场景组合。
