## 门控1：代码规范

**拦截内容**：模糊码、命名与编码约定、格式不一致

| 维度 | 选型 | 说明 |
|---|---|---|
| **格式化** | `clang-format` | 基于 `.clang-format` 统一缩进、换行、括号风格，CI 中以 `--dry-run --Werror` 拦截 |
| **命名/风格检查** | `clang-tidy`（readability-* / modernize-*）+ `cpplint` | clang-tidy 做命名规范、include 顺序、现代C++用法；cpplint 对齐 Google C++ Style |
| **注释/文档** | `doxygen` + `clang-doc` | 检查公共 API 是否有文档注释 |

**集成方式**：pre-commit hook 跑 clang-format --dry-run；CI 阶段跑 clang-tidy 全量扫描，输出 SARIF/JSON。

## 门控2：语言、构建与基础测试

**拦截内容**：类型误用、编译告警、关键字分支缺失、构建失败

| 维度 | 选型 | 说明 |
|---|---|---|
| **编译器** | `GCC 13+` / `Clang 17+` / `MSVC 2022` | 开启 `-Wall -Wextra -Wpedantic -Werror`，将告警升级为错误 |
| **构建系统** | `CMake 3.25+` + `Ninja` | 统一构建配置，`-DCMAKE_COMPILE_WARNING_AS_ERROR=ON` |
| **单元测试** | `GoogleTest (gtest)` / `Catch2` | 覆盖率用 `gcov` / `llvm-cov`，门禁阈值可设 ≥70% |
| **类型/内存安全** | 编译器 sanitizer：`-fsanitize=address,undefined` | UBSan 拦截未定义行为，ASan 拦截内存越界/泄漏 |
| **分支覆盖** | `gcovr` / `llvm-cov report` | 检查 switch 是否缺 default、异常分支是否有测试 |

**集成方式**：CI 矩阵多编译器编译 → 运行 gtest → 覆盖率报告不达标即拦截。

---

## 门控3：静态质量与安全

**拦截内容**：可疑比较、异常调用、恒真/恒假分支、空指针解引用、内存泄漏

| 维度 | 选型 | 说明 |
|---|---|---|
| **首选静态分析** | `Clang Static Analyzer`（`scan-build`） | 路径敏感分析，检出空指针、未初始化、资源泄漏 |
| **轻量扫描** | `cppcheck` | 跨平台、无编译依赖，适合 CI 快速跑，支持 `--enable=all --error-exitcode=1` |
| **深度缺陷检测** | `Infer`（Meta 开源） | 增量分析快，支持 C/C++/ObjC，对空指针和资源泄漏强 |
| **企业级（可选）** | `Coverity` / `PVS-Studio` / `SonarQube (C/C++ Plugin)` | 商业工具，规则库更全，支持漏洞模式（CWE）映射 |
| **依赖安全** | `OSV-Scanner` / `Conan audit` | 扫描第三方库 CVE |

**集成方式**：CI 中 `scan-build make` + `cppcheck --xml` 输出，统一汇入缺陷管理平台；SonarQube 做长期质量门禁。

---

## 门控4：接口、契约与数据兼容

**拦截内容**：API 默认语义变化、返回值契约破坏、ABI/头文件不兼容

| 维度 | 选型 | 说明 |
|---|---|---|
| **ABI 兼容性** | `abidiff`（libabigail）/ `abi-compliance-checker` | 对比新旧 `.so` 的符号表、类型大小，拦截 ABI break |
| **API/头文件兼容** | `HeaderHunter` / `cxx-abi` 工具链 | 检测头文件中函数签名、类布局、默认参数变化 |
| **契约测试** | `Pact-C++` / 自研接口断言 | 对跨模块接口做消费者驱动契约测试 |
| **序列化兼容** | `Protobuf` + `buf breaking` | 对 `.proto` 做字段编号/类型变更检查；JSON Schema 同理 |
| **返回值契约** | `clang-tidy`（bugprone-unchecked-optional-access / cppcoreguidelines）+ `[[nodiscard]]` | 编译器属性 + 静态分析联合拦截忽略返回值 |

**集成方式**：发布前 diff 主干版本的头文件和 `.so`，`abidiff` 非零退出即拦截；Protobuf 用 `buf breaking` 在 CI 中对比基线。

## 统一架构（C++ 版）

```
┌──────────────────────────────────────────────────────┐
│ 门控1 代码规范     → clang-format + clang-tidy → JSON │
│ 门控2 语言与构建   → GCC/Clang + gtest + sanitizer → JSON │
│ 门控3 静态质量安全 → Clang SA + cppcheck + SonarQube → JSON │
│ 门控4 接口契约     → abidiff + buf breaking + Pact → JSON │
├──────────────────────────────────────────────────────┤
│ 门控5 Agentic CR   → OCR（确定性工程 + LLM）→ JSON    │
└──────────────────────────────────────────────────────┘
                        ↓
                 统一结果聚合 + 效能平台对接
```

**核心原则不变**：前 4 个门控全部走确定性工具链（编译器 + 静态分析 + ABI diff），OCR 不介入；OCR 只守第 5 个语义审查门控，并可对前 4 门控的告警做语义增强（如判断 Sonar 报的"可疑比较"是否真的导致业务 bug）。
