# 伪码约束下的 AI 辅助生成目标架构

本文档展开说明 LightCode 中“伪码约束下的 AI 辅助生成”路径的目标架构。

AI 辅助生成是面向复杂工程上下文的增强生成路径：业务需求先表达为标准伪码，伪码作为业务语义约束，AI Agent 再结合代码仓库、框架约定、历史实现、测试反馈和工程规范生成或修改源码。

```text
业务需求
  -> 标准伪码
  -> 伪码校验 / 语义约束提取
  -> 工程上下文检索 / 代码上下文组装
  -> AI Agent 生成 / 修改源码
  -> 编译 / 测试 / 审查
  -> 反馈修复 / 经验沉淀
```

## 1. 架构定位

AI 辅助生成承担增强和补充路径能力，目标是在编译生成规则尚未覆盖、工程上下文复杂或需要局部改造时，利用 AI 提升交付效率。

| 维度 | 定位 |
|------|------|
| 核心输入 | 标准伪码、工程上下文、存量代码、测试反馈、生成约束 |
| 核心输出 | 新增源码、修改补丁、测试代码、修复说明、审查建议 |
| 生成方式 | AI Agent 在伪码约束和工程上下文下生成 |
| 成本特征 | 生成过程依赖模型推理，会消耗 AI token |
| 质量目标 | 语义受控、上下文一致、可编译、可测试、可审查 |

该路径不能替代伪码本身。AI 可以生成源码，但业务语义必须由标准伪码承载，生成结果必须接受编译、测试和人工审查约束。

## 3. 关键模块

| 模块 | 目标能力 |
|------|----------|
| 伪码约束解析器 | 从标准伪码中提取业务对象、规则、流程、接口、异常路径和生成边界。 |
| 上下文检索器 | 检索相关源码、调用链、接口定义、配置、测试用例和历史实现。 |
| 上下文裁剪器 | 控制输入上下文范围，减少无关 token 消耗，保留关键约束。 |
| Agent 编排器 | 编排分析、生成、修改、测试、修复和说明输出等步骤。 |
| 代码生成器 | 由 AI Agent 基于伪码和上下文生成新增源码或修改补丁。 |
| 测试补齐器 | 根据伪码语义和已有测试风格补齐单元测试、集成测试或回归用例。 |
| 校验执行器 | 触发编译、测试、静态检查和格式检查，并收集失败信息。 |
| 反馈修复器 | 将编译错误、测试失败、审查意见反馈给 AI Agent 做定向修复。 |
| 沉淀分析器 | 将稳定生成模式沉淀为伪码规范、生成规则、模板或测试样例。 |

## 4. 端到端流程

1. 需求进入伪码开发工具，由人工、可视化工具或 AI 生成标准伪码。
2. 工具先对伪码做语法、语义和元数据校验，确认业务语义边界。
3. 上下文检索器根据伪码对象、接口、流程和目标文件检索工程上下文。
4. 上下文裁剪器组装最小必要上下文，包含存量代码、框架约定、测试和构建约束。
5. AI Agent 基于伪码约束和工程上下文生成源码、修改补丁或测试代码。
6. 校验执行器运行编译、测试、静态检查和格式检查。
7. 若校验失败，反馈修复器将错误信息回传给 AI Agent 做局部修复。
8. 通过校验后输出变更说明、测试结果和审查关注点。
9. 对稳定、重复出现的生成模式进行沉淀，反哺伪码编译生成路径。

## 5. 适用产物举例

| 产物类型 | 示例 |
|----------|------|
| 局部源码修改 | 在既有服务中新增接口、扩展调用链、补齐异常处理 |
| 平台扩展代码 | 插件扩展、框架适配、基础组件增强、工具链集成 |
| 迁移改造代码 | 旧接口迁移、历史逻辑适配、存量代码重构 |
| 测试代码 | 针对新增逻辑补齐单元测试、集成测试、失败用例回归 |
| 修复补丁 | 编译失败修复、测试失败修复、审查意见修复 |
| 说明产物 | 变更说明、影响范围、测试结果、风险提示 |

## 6. 建设重点

| 建设项 | 目标 |
|--------|------|
| 伪码约束协议 | 明确 AI 生成源码时必须遵守的业务语义、边界和禁止事项。 |
| 工程上下文检索 | 建立代码、调用链、配置、测试、元数据的统一检索能力。 |
| 上下文裁剪策略 | 控制 token 成本，保证输入上下文相关、完整、不过载。 |
| Agent 工具接口 | 提供读取文件、检索上下文、运行校验、生成报告等标准工具。 |
| 校验反馈闭环 | 将编译、测试、静态检查和审查意见转化为可修复反馈。 |
| 变更可追踪 | 建立需求、伪码、上下文、补丁、测试结果之间的映射关系。 |
| 经验沉淀机制 | 将可重复 AI 生成模式沉淀为模板、规则或编译生成能力。 |

## 7. 与伪码编译生成的关系

AI 辅助生成与伪码编译生成不是替代关系，而是演进关系：

- 当生成规则明确、产物结构稳定时，优先走伪码编译生成。
- 当工程上下文复杂、生成规则尚未固化时，走 AI 辅助生成。
- AI 辅助生成中反复出现的稳定模式，应沉淀为伪码规范、IR 结构、生成模板或代码生成规则。
- 最终目标是让高频、稳定、可模板化的场景逐步回到低成本、可重复的伪码编译生成路径。
