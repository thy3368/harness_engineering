# 06 数据导出模块异常保护规则

涵盖 UFT 数据导出模块异常保护：M标记精确使用、错误处理模式、日志规范、性能优化、数据完整性。

---

## 1 核心原则

| 原则 | 说明 |
|------|------|
| **精确保护** | 只对真正可能失败的操作使用M标记 |
| **单记录隔离** | 单个记录失败不影响其他记录，确保批量连续性 |
| **详细日志** | ERROR级别记录错误，关键参数用于诊断 |

---

## 2 DEP_001 M标记使用原则

### 必须添加M标记

**外部数据获取**（依赖外部服务，可能返回空或异常）：
```xml
<M>[AF_证券基础_根据内码获取证券信息][...]
<M>[AF_证券基础_根据内码获取行情信息表信息][...]
<M>[AF_证券基础_根据内码获取证券行情信息][...]
```

**产品信息获取**（依赖产品数据，可能不存在）：
```xml
<M>[AF_产品_根据产品序号获取产品信息][...]
<M>[AF_产品_根据单元序号获取单元信息][...]
```

**数据验证/转换**（业务规则校验，可能拒绝）：
```xml
<M>[AF_数据导出_有效性验证][...]
<M>[AF_数据导出_字段转换][...]
```

**复杂计算操作**（逻辑复杂，边界条件多）。

### 不需要添加M标记

| 操作类型 | 示例 | 原因 |
|---------|------|------|
| 遍历记录 | `<E>[遍历记录开始][...]` | 框架控制，不会失败 |
| 权限查询 | `[AF_权限_...组合查询][...]` | 内存操作，不会失败 |
| 基础数据获取 | `[获取记录][uft_cbroker(...)][...]` | 内存操作，不会失败 |

### 判断标准

- 依赖**外部服务/数据库**？→ 可能需要M
- 涉及**业务规则校验**？→ 可能需要M
- 是**内存读取/遍历**？→ 不需要M

## 3 DEP_002 错误处理模式

### 标准模式

```xml
<M>[操作名称][参数列表][输出列表]
[处理失败]
{
    [记录日志][CNST_DLOGERROR][][操作描述失败，跳过当前记录][关键参数, @error_no, @error_info]
    [继续执行]
    continue;
}
```

### 关键要素

| 要素 | 要求 |
|------|------|
| `continue;` | 必须，跳过当前记录继续下一条 |
| `[记录日志]` | 必须，记录失败原因和关键参数 |
| `CNST_DLOGERROR` | 必须，ERROR级别 |
| `@error_no, @error_info` | 必须，系统错误码和错误信息 |

### 常见错误

```yaml
# ❌ 缺少 continue
[处理失败]
{
    [记录日志][CNST_DLOGERROR][][获取证券信息失败][@error_no, @error_info]
}

# ❌ 日志缺少关键业务参数
[记录日志][CNST_DLOGERROR][][操作失败][]

# ✅ 完整模式
[处理失败]
{
    [记录日志][CNST_DLOGERROR][][获取证券信息失败，跳过当前记录][@secu_code, @error_no, @error_info]
    [继续执行]
    continue;
}
```

## 4 DEP_003 日志记录规范

### 格式

```
[记录日志][CNST_DLOGERROR][][操作描述][参数1, 参数2, @error_no, @error_info]
```

### 参数选择

| 参数类型 | 示例 | 用途 |
|---------|------|------|
| 业务标识 | `@secu_code`, `@product_no` | 定位具体记录 |
| 系统错误 | `@error_no`, `@error_info` | 获取失败原因 |

### 示例

```xml
[记录日志][CNST_DLOGERROR][][获取证券信息失败，跳过当前记录][@secu_code, @error_no, @error_info]
[记录日志][CNST_DLOGERROR][][获取产品信息失败，跳过当前记录][@product_no, @error_no, @error_info]
[记录日志][CNST_DLOGERROR][][有效性验证失败，跳过当前记录][@batch_no, @error_no, @error_info]
```

## 5 DEP_004 性能优化原则

- **精确M标记**：每个M标记都有"可能失败"的理由，不是 blanket 保护
- **避免过度保护**：内存操作加M标记只增加开销无收益
- **监控M命中率**：过高说明数据质量问题，零触发可评估移除

```yaml
# ✅ 合理：外部数据获取
<M>[AF_证券基础_根据内码获取证券信息][...]

# ❌ 过度保护：内存遍历
<M>[遍历记录开始][...]
```

## 6 DEP_005 数据完整性保护

### 完整模板

```xml
<E>[遍历记录开始][数据表名][条件][输出字段列表]
{
    <M>[AF_证券基础_根据内码获取证券信息][...][...]
    [处理失败]
    {
        [记录日志][CNST_DLOGERROR][][获取证券信息失败，跳过当前记录][@secu_code, @error_no, @error_info]
        [继续执行]
        continue;
    }

    <M>[AF_数据导出_有效性验证][...][...]
    [处理失败]
    {
        [记录日志][CNST_DLOGERROR][][有效性验证失败，跳过当前记录][@batch_no, @error_no, @error_info]
        [继续执行]
        continue;
    }

    // 其他业务逻辑（非关键操作无需M标记）
}
[遍历记录结束]
```

### 数据质量监控

- 错误日志统计失败记录数和失败原因
- 批量结束后对比：遍历总数 vs 成功数，差异过大触发告警

## 7 实施检查清单

- [ ] 所有AF调用是否逐一分析M标记需求（非批量添加）
- [ ] M标记`[处理失败]`块是否包含`[记录日志]` + `continue;`
- [ ] 日志是否包含关键业务参数 + `@error_no` + `@error_info`
- [ ] 是否存在不必要的M标记（内存操作、遍历操作）
- [ ] 是否缺少必要的M标记（外部数据获取、业务校验）
- [ ] 日志描述是否清晰（能区分不同操作的失败）
- [ ] 遍历循环内每个M标记是否保证单记录隔离
