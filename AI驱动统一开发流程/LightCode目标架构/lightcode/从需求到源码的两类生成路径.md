# LightCode 从需求到源码的两类生成路径

LightCode 的源码生成以伪码为统一中间表达。业务需求先转为标准伪码，再根据场景选择不同的源码生成路径。

## 路径一：伪码编译生成

```text
需求 -> 标准伪码 -> 编译器 / 代码生成器 -> 源码
```

伪码编译生成是确定性生成路径。标准伪码经过语法、语义和元数据校验后，由编译器或代码生成器生成目标源码。

### 适用场景

- 业务规则清晰，生成规则稳定，例如 CRM 线索分配、客户评级、估值规则等业务逻辑。
- 代码结构可模板化、可标准化，例如标准 CRUD、参数校验、SQL 查询、报表导出等。
- 对一致性、可追溯性、可重复生成要求高，例如批量生成服务接口、数据模型、测试代码等。

### 特点

- 生成结果稳定，可重复。
- 生成阶段不依赖模型推理，不消耗 AI token。
- 源码可追踪到对应伪码和模型来源。
- 适合作为长期主路径建设。

## 路径二：伪码约束下的 AI 辅助生成

```text
需求 -> 标准伪码 -> AI Agent + 工程上下文 -> 源码 -> 编译 / 测试 / 审查
```

AI 辅助生成是面向复杂工程上下文的增强路径。伪码仍然作为业务语义约束，AI Agent 结合代码仓库、框架约定、历史实现和测试反馈生成源码。

### 适用场景

- 工程上下文复杂，难以完全模板化，例如平台框架、基础组件、插件扩展等。
- 需要参考存量代码、框架约定或历史实现，例如在既有服务中新增接口、扩展调用链、适配历史逻辑等。
- 需要进行局部补全、修复、重构或迁移，例如补齐异常处理、修复测试失败、迁移旧接口实现等。

### 特点

- 灵活性高，能处理非标准工程细节。
- 生成质量依赖上下文质量、测试反馈和审查机制。
- 适合作为伪码编译生成的补充路径。

## 两类路径对比

| 维度 | 伪码编译生成 | 伪码约束下的 AI 辅助生成 |
|------|--------------|--------------------------|
| 生成方式 | 编译器 / 代码生成器确定性生成 | AI Agent 结合工程上下文生成 |
| 核心优势 | 稳定、可重复、可追溯 | 灵活、适应复杂工程上下文 |
| AI token 成本 | 生成阶段不消耗 AI token | 生成过程会消耗 AI token |
| 主要约束 | 依赖伪码规范和生成规则完备度 | 依赖上下文质量、测试反馈和审查机制 |
| 架构定位 | 长期主路径 | 增强和补充路径 |
