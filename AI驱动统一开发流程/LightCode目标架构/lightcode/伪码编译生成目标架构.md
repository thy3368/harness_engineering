# 伪码编译生成目标架构

本文档展开说明 LightCode 中“伪码编译生成”路径的目标架构。

伪码编译生成是从需求到源码的确定性生成路径：业务需求先表达为标准伪码，伪码经过校验、归一化和 IR 转换后，由编译器 / 代码生成器生成 Java / C++ / SQL、配置和测试代码等工程产物。

该路径拆为两部分：

- **伪码及编译器**：提供标准伪码、解析校验、IR、编译生成、诊断和报告能力。
- **伪码设计器**：提供面向用户、可视化建模和 AI 的伪码编辑、设计和调用入口。

两者必须解耦。伪码设计器不直接依赖编译器内部实现，只通过标准伪码文件、CLI / LSP / MCP 工具接口、诊断结果和生成报告与伪码及编译器交互。

```text
业务需求
  -> 伪码设计器
  -> 标准伪码文件
  -> 伪码及编译器
  -> 语法校验 / 语义校验 / 元数据校验
  -> 统一 IR
  -> 编译器 / 代码生成器
  -> 目标源码 / 配置 / 测试代码
  -> 生成报告 / 追踪映射
```

## 1. 架构定位

伪码编译生成承担长期主路径能力，目标是让常规业务逻辑可以稳定、低成本、可追溯地生成源码。

| 维度 | 定位 |
|------|------|
| 核心输入 | 标准伪码、元数据规范、生成参数、工程模板 |
| 核心输出 | Java / C++ / SQL 源码、配置、测试代码、生成报告 |
| 生成方式 | 编译器 / 代码生成器确定性生成 |
| 成本特征 | 生成阶段不依赖模型推理，不消耗 AI token |
| 质量目标 | 可重复、可构建、可测试、可追踪 |

该路径不替代 AI 辅助生成。AI 可以参与需求结构化、伪码生成和错误修复，但源码生成阶段以编译器和代码生成器为主。

## 2. 总体解耦架构

```text
┌──────────────────────────────────────────────┐
│ 伪码设计器                                    │
│ - 需求结构化 / 伪码编辑 / 可视化设计            │
│ - AI 辅助伪码生成 / 诊断展示 / 生成触发         │
└──────────────────────────────────────────────┘
                    │
                    │ 标准伪码文件 / CLI / LSP / MCP / 诊断协议
                    ▼
┌──────────────────────────────────────────────┐
│ 伪码及编译器                                  │
│ - 伪码规范 / 解析器 / 语义校验 / 统一 IR        │
│ - 编译器 / 代码生成器 / 生成报告 / 追踪映射     │
└──────────────────────────────────────────────┘
                    │
                    ▼
┌──────────────────────────────────────────────┐
│ 工程产物层                                    │
│ - Java / C++ / SQL / 配置 / 测试代码            │
│ - 编译结果 / 测试结果 / 生成报告                │
└──────────────────────────────────────────────┘
```

解耦原则：

- 伪码设计器只认标准伪码、工具接口和诊断结果，不直接调用编译器内部类、AST 私有结构或生成器实现。
- 伪码及编译器只提供标准能力，不承载设计器 UI、画布状态、表单状态和用户操作历史。
- 设计器可以替换，编译器可以升级，只要标准伪码和接口契约不变，双方不互相阻塞。
- AI 可以辅助生成伪码和解释诊断，但不能绕过标准伪码和编译器直接固化业务语义。

## 3. 第一部分：伪码及编译器

伪码及编译器是底层标准能力层，负责定义伪码表达、校验业务语义、构建统一 IR，并确定性生成工程产物。

### 3.1 职责边界

| 职责 | 说明 |
|------|------|
| 伪码规范 | 定义语法、语义、版本、禁用写法、元数据引用和示例。 |
| 解析与格式化 | 将伪码文本解析为 AST，并提供格式化、语法诊断和版本识别。 |
| 语义校验 | 校验类型、字段、接口、流程、规则、异常路径和元数据引用。 |
| 统一 IR | 将伪码语义归一化为稳定 IR，供生成、测试、影响分析和追踪使用。 |
| 编译生成 | 基于 IR 和生成规则生成 Java / C++ / SQL、配置和测试代码。 |
| 诊断与报告 | 输出错误位置、失败原因、生成报告、追踪映射和影响范围。 |

### 3.2 工具链与内部模块

伪码及编译器应像 Rust、Go、TypeScript 等高级语言一样，提供完整工具链，而不只是一个代码生成器。工具链负责对外暴露稳定能力，内部模块负责支撑这些能力。

| 对外能力 | 类比 | 内部模块 | 目标能力 |
|----------|------|----------|----------|
| 标准伪码文件 | source file | 伪码规范 | 作为设计器、AI Agent、编译器共同读写的业务语义载体。 |
| 伪码编译器 | `rustc` | 伪码解析器、语义校验器、IR 构建器 | 解析伪码、执行语义校验、构建 IR，并驱动目标代码生成。 |
| 伪码 CLI | `cargo` | 执行编排器 | 提供统一命令入口，支持初始化、校验、格式化、生成、测试、报告和流水线集成。 |
| 格式化工具 | `rustfmt` | 格式化器 | 统一伪码格式，减少人工、AI、设计器生成结果的风格差异。 |
| 规则检查工具 | `clippy` | 规则检查器 | 检查可维护性、禁用写法、命名规范、元数据引用风险和生成风险。 |
| 语言服务 | `rust-analyzer` | LSP 服务 | 提供补全、跳转、悬浮说明、引用查找、诊断和快速修复。 |
| 代码生成工具 | codegen | 生成规则引擎、代码生成器、配置生成器 | 基于 IR 生成 Java / C++ / SQL、配置和测试代码。 |
| 测试工具 | `cargo test` | 测试执行器、测试代码生成器 | 执行伪码级测试、生成代码测试、回归测试和覆盖度统计。 |
| 文档工具 | `cargo doc` | 文档生成器 | 从伪码、元数据和生成报告生成接口说明、规则说明和追踪文档。 |
| 资产管理工具 | registry | 资产管理器 | 管理可复用伪码组件、规则模板、生成模板和测试模板。 |
| 版本与兼容检查 | semver check | 兼容性检查器 | 检查伪码规范版本、元数据版本、生成模板版本和向后兼容性。 |
| 生成差异工具 | diff | 差异分析器 | 对比伪码变更前后的生成产物、影响范围和风险点。 |
| 追踪映射工具 | source map | 追踪映射器 | 建立需求、伪码、IR、生成源码、测试结果之间的可追踪关系。 |
| 诊断与报告工具 | diagnostics | 诊断协议、生成报告器 | 输出错误位置、修复建议、生成结果、失败原因、依赖关系和风险提示。 |
| Agent 工具接口 | MCP | MCP / Agent 工具服务 | 供 AI Agent 调用校验、生成、测试、报告和反馈修复能力。 |
| CI/CD 集成工具 | build pipeline | 流水线适配器 | 在流水线中执行 check、generate、test、report，保证生成结果可持续验证。 |

建议形成统一 CLI 命令族：

```text
pseudo init       初始化伪码工程
pseudo parse      解析伪码并输出 AST / IR 摘要
pseudo check      执行语法、语义、元数据引用校验
pseudo fmt        格式化伪码
pseudo lint       执行规则检查和风险检查
pseudo generate   生成 Java / C++ / SQL、配置和测试代码
pseudo test       执行伪码测试和生成代码测试
pseudo diff       输出伪码变更带来的生成差异和影响范围
pseudo doc        生成接口、规则、模型和追踪文档
pseudo report     输出诊断报告、生成报告和追踪报告
```

工具链建设原则：

- 所有工具都以标准伪码文件和元数据规范为输入，不依赖设计器内部状态。
- CLI 是权威入口，IDE、设计器、AI Agent、CI/CD 都复用同一套命令能力。
- 诊断、报告、追踪映射必须结构化输出，方便设计器展示和 AI Agent 消费。
- 工具链能力优先保证 `check -> generate -> test -> report` 的闭环，再逐步增强资产管理、文档和兼容性检查。

### 3.3 不负责事项

- 不负责设计器页面布局、画布交互、表单状态和用户操作历史。
- 不负责 AI 对话上下文、Prompt 编排和模型选择。
- 不直接读取设计器内部状态；只读取标准伪码、元数据、工程上下文和生成参数。
- 不把 UI 组件、IDE 插件实现或可视化节点结构写入编译器内部。

## 4. 第二部分：伪码设计器

伪码设计器是面向用户、可视化建模和 AI 的开发入口，负责把业务需求、可视化设计和 AI 交互结果沉淀为标准伪码。

### 4.1 职责边界

| 职责 | 说明 |
|------|------|
| 需求结构化 | 将自然语言需求、变更说明和测试目标整理为可落地的伪码编辑任务。 |
| 伪码编辑 | 提供文本编辑、结构化编辑、可视化设计、局部修改和版本管理；可视化设计结果必须转换为标准伪码后再进入编译器。 |
| AI 辅助 | 调用 AI 生成伪码、解释诊断、修复错误、生成或补齐伪码测试用例，并输出变更说明。 |
| 用户交互 | 展示诊断、差异、影响范围、生成报告和审查关注点。 |
| 生成触发 | 通过 CLI / MCP 触发校验、格式化、生成、测试和报告输出；通过 LSP 获取编辑期诊断、补全、跳转和悬浮说明。 |
| 上下文组织 | 为 AI Agent 组装需求、伪码、诊断、元数据、代码片段和测试反馈。 |

### 4.2 对外依赖

| 依赖 | 用途 |
|------|------|
| 标准伪码规范 | 约束设计器生成和编辑的内容必须合法。 |
| LSP 服务 | 提供编辑时诊断、补全、跳转和悬浮说明。 |
| CLI / MCP 工具 | 提供校验、格式化、生成、测试、报告，以及工程上下文和元数据上下文检索能力。 |
| 元数据服务 | 提供字段、接口、错误码、权限和引用关系。 |
| 工程上下文服务 | 提供代码检索、调用链、配置、测试用例和历史实现。 |
| AI Agent | 提供需求理解、伪码生成、错误修复和说明输出。 |

### 4.3 不负责事项

- 不实现编译器语法解析、类型系统、IR 构建和代码生成规则。
- 不把画布节点、表单字段或 UI 状态作为编译器输入。
- 不维护一套与编译器不一致的本地语义规则。
- 不把设计器本地校验结果作为最终语义结论；权威诊断来自伪码及编译器。
- 不绕过标准伪码直接驱动源码生成。

## 5. 编译生成流程

```text
需求 / 变更目标
  -> 伪码设计器整理任务
  -> 生成或修改标准伪码
  -> 调用伪码及编译器做 parse / check / format
  -> 基于诊断结果修复伪码
  -> 构建统一 IR
  -> 编译器 / 代码生成器生成工程产物
  -> 编译 / 测试 / 差异检查
  -> 输出源码、配置、测试代码、生成报告和追踪映射
```

关键约束：

1. 编译器的权威输入是标准伪码，不是设计器内部状态。
2. 设计器负责编辑、展示和触发，编译器负责解析、校验、IR 和生成。
3. 生成产物必须具备从源码回溯到伪码、IR 和模型来源的映射关系。
4. 稳定生成规则沉淀在编译器和生成模板中，不沉淀在设计器 UI 逻辑中。

## 6. 适用产物举例

| 产物类型 | 示例 |
|----------|------|
| Java 服务代码 | 标准服务接口、参数校验、领域服务、DTO、测试桩 |
| C++ 业务代码 | 核心交易逻辑、规则计算、低延迟业务处理 |
| SQL 产物 | 查询 SQL、聚合 SQL、视图、数据处理脚本 |
| 配置产物 | 接口配置、规则配置、运行参数、部署配置 |
| 测试产物 | 单元测试、集成测试、回归测试、测试数据模板 |

## 7. 建设重点

| 建设项 | 目标 |
|--------|------|
| 标准伪码契约 | 让设计器、AI Agent、编译器围绕同一份伪码语义工作。 |
| 编译器 Headless 化 | 编译器能力通过 CLI / LSP / MCP 暴露，避免被 IDE 或设计器绑定。 |
| 设计器轻内核化 | 设计器只做交互、上下文和工具编排，不复制编译器语义。 |
| 标准伪码规范 | 明确语法、语义、版本、禁用写法和示例。 |
| 统一 IR | 让生成器依赖稳定 IR，而不是直接依赖文本伪码。 |
| 元数据规范 | 统一字段、类型、接口、错误码、权限和引用关系。 |
| 多目标生成器 | 支持 Java / C++ / SQL、配置和测试代码生成。 |
| 工程模板适配 | 适配不同产品线、目录结构、构建方式和框架约定。 |
| 追踪与报告 | 建立需求、伪码、IR、源码、测试之间的可追踪链路。 |
| 生成质量验证 | 接入编译、测试、差异检查和回归验证。 |

## 8. 与 AI 辅助生成的关系

伪码编译生成与 AI 辅助生成不是互斥关系，而是分工关系：

- AI 适合参与需求理解、伪码生成、诊断解释和修复建议。
- 编译器适合承担稳定、可重复、低成本的源码生成。
- 当生成规则明确时，优先走伪码编译生成。
- 当工程上下文复杂、规则尚未固化时，可走 AI 辅助生成，并将成熟经验沉淀回伪码规范、IR 和生成规则。
