# 伪码编译生成当前实现架构及演进计划

本文档基于《一体化开发工具20260416.md》抽取“伪码编译生成”相关信息，说明当前实现架构、主要问题、问题解决后的价值点，以及后续演进计划。

## 1. 当前实现架构

当前伪码编译生成以 **UF30 伪代码工具** 为主要起点，同时吸收 **Ares Studio** 的成熟实践，逐步统一为公司级伪代码体系。

```text
当前状态

Ares Studio 伪代码体系              UF30 伪代码工具
- Eclipse 4.6                       - IDEA 2021.3
- 偏 C/C++ 平台                     - 偏 Java 平台
- 编译目标偏 C/C++                  - 编译目标偏 Java
- 已有成熟业务实践                  - HEP 功能较完整
        │                                  │
        └────────── 语法相似，但分立维护 ───┘
                           │
                           ▼
                 UDP / LightCode 统一伪码体系
                           │
                           ▼
              Java / C++ / SQL 多目标代码生成
```

### 1.1 工具形态

| 当前能力 | 现状 |
|----------|------|
| UF30 伪代码工具 | 当前最具竞争力的起点，计划收编并作为首个可用版本发布。 |
| Ares Studio 伪代码 | 与 UF30 语法相似，承载于 C/C++ 平台，已有成熟实践。 |
| IDEA 插件 | UF30 当前主要形态，过渡期继续维护。 |
| VSCode 插件 | 目标主力形态，逐步承接伪代码编辑、补全、错误提示、编译触发能力。 |
| CLI 核心 | 目标 Headless 形态，承载伪代码编译器、元数据引擎、代码生成器、校验引擎。 |

### 1.2 编译生成能力

| 能力 | 当前状态 |
|------|----------|
| Java 生成 | UF30 侧已有基础，2026 年目标是形成伪代码 -> Java 代码生成 MVP。 |
| C++ 生成 | Ares Studio 侧有 C/C++ 经验，目标体系中需要吸收并统一。 |
| SQL 生成 | 目标体系规划支持，作为 2026 年 8-12 月编译器增强方向之一。 |
| 元数据驱动生成 | 依赖 HEP 现有元数据规范修订扩展，需与伪代码语法规范同步治理。 |
| 测试与报告 | 当前需要补强生成质量验证、测试覆盖、生成报告和追踪映射。 |

## 2. 当前主要问题

| 问题 | 表现 | 影响 |
|------|------|------|
| 伪代码体系重复维护 | Ares Studio 与 UF30 语法相似，但由不同团队分别维护。 | 知识无法共享，维护成本重复，难以形成公司级统一中间表达。 |
| 编译器 / 解析器分立 | Ares Studio 偏 C/C++，UF30 偏 Java，两套编译器分别演进。 | 无法互通，Java / C++ / SQL 多目标生成难以统一。 |
| IDE 形态碎片化 | Eclipse、IDEA、VSCode、Web 等多入口并存。 | 用户体验割裂，插件能力重复建设，迁移和维护成本高。 |
| UF30 与 IDEA 插件耦合 | UF30 当前为 IDEA 插件形态，编译器与 IDE 耦合较高。 | 抽取 CLI 核心存在风险，影响 VSCode 化和 CI/CD 集成。 |
| 元数据规范不统一 | HEP、HSDDML、HFlow、YML、XML 等格式分散。 | 伪码引用、代码生成、影响分析和 AI 上下文难以统一。 |
| 生成质量验证不足 | 编译错误信息、边界 case、回归测试、生成报告仍需加强。 | 生成代码质量不稳定，推广时需要较高人工兜底。 |

## 3. 问题解决后的价值点

| 解决方向 | 价值点 |
|----------|--------|
| 统一伪代码体系 | 消除 Ares Studio 与 UF30 重复维护成本，让业务逻辑沉淀为公司级统一中间表达。 |
| 统一编译器 / 代码生成器 | 支持 Java / C++ / SQL 多目标输出，避免不同平台各自建设生成规则。 |
| CLI 核心化 | IDE 只做 UI 适配，编译、校验、生成可在 IDE、流水线、AI Agent 中复用。 |
| VSCode 自封装 | 用统一 IDE 承接伪码开发、元数据管理、代码生成和 AI 能力，降低工具碎片化。 |
| 元数据规范同步治理 | 让伪码、元数据、生成代码、测试和影响分析具备统一引用关系。 |
| 生成质量闭环 | 通过编译、测试、差异检查和生成报告提升可用性，降低人工审查成本。 |
| AI token 成本降低 | 高频稳定场景走编译生成，生成阶段不依赖模型推理，不消耗 AI token。 |

## 5. 演进原则

- 以 UF30 为起点，不另起炉灶，优先继承已有用户群和使用习惯。
- 以统一伪代码体系为主轴，吸收 Ares Studio 成熟实践。
- 以 CLI 核心承载编译、校验、生成能力，IDE 只做入口和交互适配。
- 以 VSCode 自封装作为长期主力形态，IDEA 插件作为过渡期维护形态。
- 以元数据规范和伪代码语法规范同步治理，保证生成结果可追踪、可测试、可复用。
