## 2. 核心组件

### 2.1 中间语言

#### 2.1.1 中间语言规格

##### 伪码规格定义（元数据规范体系）

- 统一伪代码体系作为业务逻辑的中间表达（IR），覆盖三范式，支持 Java / C++ / SQL 多目标输出。
- 方法论支撑。
- MDD 模型驱动开发。
- 五级流程建模。
- 数据建模。

##### 逻辑架构

| 维度 | 内容 |
|------|------|
| 职责 | 作为业务逻辑的统一中间表达，承接需求、模型、规则、流程等业务语义，支撑多目标语言生成、伪码测试、影响分析和资产复用。 |
| 输入契约 | 接收需求、业务模型、数据模型、流程模型、规则模型和元数据规范。 |
| 输出契约 | 输出标准统一伪代码 IR，作为测试、翻译、复用和影响分析的基础。 |
| 交互契约 | 被开发工具、翻译器、测试工具和中间语言仓库引用。 |
| 质量契约 | 保持透明、稳定、向下兼容、可审查、可测试、可生成。 |

##### 实现架构

- HSDDML。
- HFlow JSON。
- 大数据 YML。
- 表设计器 XML。
- 其他元数据与 DSL 格式。

### 2.2 中间语言翻译器

#### 2.2.1 逻辑架构

| 维度 | 内容 |
|------|------|
| 职责 | 将统一伪代码 IR 翻译为目标语言代码，支持 LLM 出码、原生 Java / C++ 代码解析、原生 Java / C++ 代码出码，以及存量代码理解、迁移和影响分析。 |
| 输入契约 | 接收统一伪代码 IR、元数据规范、翻译规则和目标语言生成参数。 |
| 输出契约 | 输出 Java / C++ / SQL 等目标产物，以及原生代码解析后的标准结构化结果。 |
| 交互契约 | 与中间语言、开发工具、测试工具、代码仓库和构建流水线交互。 |
| 质量契约 | 生成前完成语法、语义和元数据引用校验，目标代码需要能追踪到对应伪码和模型来源。 |

#### 2.2.2 实现架构

- 代码生成器。
- JRES。
- CRES。

### 2.3 开发工具

#### 2.3.1 逻辑架构

| 维度 | 内容 |
|------|------|
| 职责 | 提供伪码开发入口，支持可视化、编辑、AI 开发、伪码校验、测试、生成、影响分析，以及 Claude Code、Codex 等 AI Agent 接入。 |
| 输入契约 | 接收需求文档、模型文件、伪码文件、测试文件、AI 上下文和用户操作指令。 |
| 输出契约 | 输出诊断结果、测试报告、生成结果、影响分析结果和更新后的伪码资产。 |
| 交互契约 | IDE、CLI、MCP、直接文件等入口调用同一套能力；AI Agent 通过 MCP 或标准工具接口访问上下文和执行能力。 |
| 质量契约 | 入口能力一致，文件可版本管理，编辑、校验、测试、生成等操作接口一致。 |

#### 2.3.2 实现架构

- vs code studio
- IDE（GUI）。
- CLI。
- MCP。
- 直接文件。
- Claude Code / Codex 接入能力。

### 2.4 中间语言仓库

#### 2.4.1 逻辑架构

| 维度 | 内容 |
|------|------|
| 职责 | 管理可复用伪码组件、模型模板、规则模板、测试模板和翻译模板，支撑跨项目复用、AI 检索推荐和领域知识沉淀。 |
| 输入契约 | 接收项目交付后的伪码组件、模型模板、测试模板、翻译规则、缺陷修复和领域经验。 |
| 输出契约 | 输出可检索、可复用、可适配的组件、模板、规则和知识资产。 |
| 交互契约 | 与开发工具、AI Agent、翻译器、测试工具和项目仓库交互。 |
| 质量契约 | 资产具备标准结构、版本、兼容性、变更记录、输入参数、适配规则和测试模板。 |
