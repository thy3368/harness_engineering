### PDU 规格模板与 skill 的统一管理方案

技术平台下有多个 PDU，各自维护需求规格模板、补充约束和对应 skill。后续如果要持续推进，建议采用“**统一基线、分层扩展、集中治理、分角色检查**”的方式统一管理。

#### 1. 仓库管理方式

建议采用“每个 PDU 一个 Git 仓库，架构部一个 Git 仓库管理通用规则”的方式进行管理，避免职责混杂，也便于各 PDU 独立维护和持续演进。  
架构部仓库负责维护通用文档规格、通用约束和治理规则，各 PDU 仓库在此基础上补充本领域模板、约束和 skill。



#### 2. 目录结构建议

建议采用“架构部通用规则仓库 + 各 PDU 独立仓库”的目录组织方式。

```text
architecture-spec-repo/
  common/
    templates/
    constraints/
    skills/

pdu-a-spec-repo/
  templates/
  constraints/
  skills/
  checklist/
  examples/
```

其中，`architecture-spec-repo/` 由架构部维护，主要存放通用模板、通用约束、通用 skill 和治理规则；`pdu-a-spec-repo/` 代表各 PDU 自有仓库，用于维护本领域的模板、约束、skill、checklist 和示例。
pdu-a-spec-repo的目录结构各pdu可以调整，通用约束引用architecture-spec-repo

#### 3. 通用规格放置方式

通用规格建议统一放在架构部维护的 `architecture-spec-repo/` 中，由架构部集中维护和重点检查。  
各 PDU 仅在各自仓库中补充本领域特殊约束，不单独改写通用基线。

#### 4. 管理对象统一方式

建议将每个 PDU 的治理对象统一定义为一个“规格包”，包括：模板、约束、skill、checklist 和示例。  

#### 5. 角色分工

**各 PDU 成员负责：**维护本 PDU 的模板、约束和专属 skill，并按统一规范使用。  
**质量运营负责：**维护治理流程，组织检查、统计和整改闭环。  
**技术平台研发管理部架构部负责：**维护通用架构基线，通用文档规格。




整体上，建议采用“**架构部统一维护通用规则仓库 + 各 PDU 独立维护各自仓库**”的方式推进，便于质量运营横向治理，也便于架构部统一把控通用规格要求。
