### PDU 规格模板与 skill 的统一管理方案

技术平台下有多个 PDU，各自维护需求规格模板、补充约束和对应 skill。后续如果要持续推进，建议采用“**统一基线、分层扩展、集中治理、分角色检查**”的方式统一管理。

#### 1. 统一仓库

建议将各 PDU 的模板、约束和 skill 统一纳入同一个 Git 仓库管理，避免分散维护和版本失控。  
逐步各 PDU 在统一基线上护展和补充。

#### 2. 目录结构建议

建议按“通用基线 / PDU 扩展 / skill / 治理规则”分层存放：

```text
spec/
  governance/
  common/
    templates/
    constraints/
  pdus/
    pdu-a/
      templates/
      constraints/
      skills/
  skills/
    common/
```


架构部建个仓库。
==================



其中，`common/` 放通用模板和约束，`pdus/` 放各 PDU 的差异化补充，`skills/common/` 放平台通用 skill，`governance/` 放流程和检查清单。

#### 3. 通用规格放置方式

架构部要求建议统一放在 `common/constraints/architecture-baseline.md`，由架构部重点检查。  
各 PDU 只补充本领域特殊约束，不单独改写通用基线。

#### 4. 管理对象统一方式

建议将每个 PDU 的治理对象统一定义为一个“规格包”，包括：模板、约束、skill、checklist 和示例。  
即：模板定义写什么，约束定义怎么写，skill 负责初检，checklist 用于人工复核。

#### 5. 角色分工

**各 PDU 成员负责：**维护本 PDU 的模板、约束和专属 skill，并按统一规范使用。  
**质量运营负责：**维护治理流程，组织检查、统计和整改闭环。  
**技术平台研发管理部架构部负责：**维护通用架构基线，通用文档规格。




整体上，建议采用“**一个统一仓库 + 一套通用基线 + PDU 分层扩展 + ”的方式推进，便于质量运营横向治理，也便于架构部统一把控文档能用规格要求。
