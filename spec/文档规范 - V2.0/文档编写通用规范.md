# 文档编写通用规范

## 一、内容编写规范（强制要求）

### 1. 结构规范

- 一级标题：1、2、3...
- 二级标题：1.1、1.2、2.1、2.2...
- 三级标题：1.1.1、1.1.2、2.1.1、2.1.2...
- 四级标题（可选）：1.1.1.1、1.1.1.2...（最多四级，避免层级冗余）
- 核心规则：
  1. 层级编号全文统一，不跳级、不重复
  2. 一级标题为核心章节，二级为模块，三级为具体内容，同级内容平行不交叉
  3. 每个标题下必有对应内容，无"空标题"
  4. 标题统一对齐，正文缩进一致，图表/列表紧跟对应标题不悬空

### 2. 语言规范

- 使用正式书面语，语句通顺简洁，避免长句、复杂句，杜绝口语化表达、未解释的缩略语。
- 同一术语全文统一（如"统一登录"不混用"单点登录"），专业术语首次出现需附带解释。
- 技术名词英文首次出现需标注中文（例：OAuth2.0（开放授权））。
- 禁用模糊表述（如 “大概”“可能”），精准描述操作路径。
- 操作按钮、菜单用【】标出，例：点击【登录】按钮。
- 操作步骤用阿拉伯数字有序罗列，不省略关键环节。
- 操作步骤、命令、参数需精准无误，明确操作路径、命令格式，避免歧义，关键操作、参数需加粗标注。
- 异常场景、注意事项需突出显示（可使用高亮块），提醒开发人员重点关注。

### 3. 图表规范

- 架构图强制要求：包含分层、箭头、说明、图例四要素
- 图表编号规则：图+章节号+序号（例：图3-1 总体技术架构图）
- 表格编号规则：表+章节号+序号（例：表4-1 核心技术能力清单）
- 排版要求：图/表紧跟对应文字描述，不悬空，与上下文保留适当间距

### 4. 界面截图规范

- 截图清晰完整，无水印、无遮挡，界面文字可辨，色彩正常。
- 关键区域用红色箭头、方框标注，醒目易懂。
- 截图尺寸统一，不拉伸变形，风格、标注样式一致。
- 每个操作步骤对应一张截图，复杂步骤分步配图。
- 截图紧跟文字说明，标注编号（例：图 1-1 产品主界面），全文连贯。

### 5. 技术规范

- 版本号必须精确（例：JDK17、SpringBoot3.5、鸿蒙7、iOS27）
- 性能指标量化呈现（例：启动耗时≤3秒、并发支持10万+、内存占用≤2G、可用性99.99%）

### 6. 特性价值规范

每一个技术点必须对应商业/业务价值，禁止仅描述功能：

- 错误示例："实现统一登录功能"
- 正确示例："统一登录能力提升用户操作效率，降低多系统账号管理成本"
- 价值方向：提升XX效率、降低XX成本、增强XX安全、支撑XX规模化

### 7. 字段说明规范

- 字段限制：明确各字段类型、长度、格式、必填属性，禁止模糊表述。
- 字段操作规则：新增（必填字段、重复校验）、删除（删除条件、是否可恢复）、修改（可修改 / 不可修改字段）、查询（查询条件、范围）。
- 适用场景限制：明确适用角色、适用场景及禁止操作场景。

### **8.** **配置项对应赋值说明编写要求**

配置项说明需采用表格形式（符合格式规范），按模块分类整理，每个配置项需明确以下信息，确保赋值无歧义、无错误：

| 配置项名称        | 配置路径                      | 数据类型 | 赋值范围   | 默认值 | 赋值说明                                                     | 使用场景                           | 赋值错误影响                             |
| ----------------- | ----------------------------- | -------- | ---------- | ------ | ------------------------------------------------------------ | ---------------------------------- | ---------------------------------------- |
| 示例：server.port | config/application.properties | Integer  | 1024-65535 | 8080   | 配置产品服务端口，需确保端口未被占用，赋值需为整数，不可超出端口范围 | 产品二次开发部署时，自定义服务端口 | 端口超出范围或被占用，将导致服务启动失败 |

补充说明：

- 配置项名称：与配置文件内字段完全一致，区分大小写，作为 AI 识别唯一标识。
- 赋值说明需简洁明了，明确赋值规则、赋值方法，复杂配置项需提供赋值示例。  
- 赋值范围需精准（如整数范围、字符串长度、枚举值等），枚举类型需列出所有可选值及对应含义，格式为 “值 - 含义”，便于 AI 提取关联关系。
- 数据类型需明确（如String、Integer、Boolean、Array、Object等），复杂类型需说明具体格式。
- 敏感标注：账号、密码、密钥必须标注【保密】，禁止明文展示，建议通过环境变量注入，AI 可自动识别敏感字段；
- 使用场景需明确该配置项在二次开发中的具体应用场景，避免配置项滥用。
- 多环境配置：明确开发 / 测试 / 生产环境差异。
- 生效说明：明确配置修改后的生效方式（如 “需重启服务”），避免操作遗漏。

### **9.** **示例代码解析说明编写要求**

示例代码需覆盖二次开发核心场景（如接口调用、配置修改、功能扩展、数据交互等），解析需详细易懂，具体要求如下：

•     代码规范：示例代码需符合行业开发规范及公司代码标准，格式整齐、注释清晰，命名规范，可直接复制套用（需标注可修改部分）。

•     场景匹配：每个示例代码对应明确的二次开发场景，说明代码的应用场景、实现功能，让开发人员快速匹配自身需求。

•     解析详细：分模块解析代码，包括核心逻辑说明、关键参数解析、调用方法、修改注意事项，重点标注易出错、需自定义修改的部分。

•     异常提示：说明代码运行过程中可能出现的异常、异常原因及处理方法，帮助开发人员规避错误。

•     格式要求：代码块需标注编程语言，使用代码块格式展示，解析文字与代码块分开，逻辑清晰，重点内容加粗标注。

### **10.** **接口文档对应接口说明编写要求**

接口说明需与产品官方接口文档完全一致，按接口功能分类，每个接口需详细说明以下内容，确保接口调用准确、无遗漏：

•     接口基本信息：明确接口名称、接口描述、请求方式（GET/POST/PUT/DELETE等）、请求地址、接口版本、适用场景，说明接口在二次开发中的作用。

•     入参说明：采用表格形式，明确入参名称、数据类型、是否必填、入参说明、取值范围，复杂入参需说明数据格式（如JSON格式示例），标注必填项，说明入参缺失或错误的影响。

•     出参说明：采用表格形式，明确出参名称、数据类型、出参说明、返回值范围，复杂出参需提供JSON格式示例，说明出参含义及使用方法。

•     异常场景说明：梳理接口调用过程中可能出现的所有异常（如参数错误、权限不足、接口超时、数据不存在等），明确异常码、异常描述、异常原因及处理方法，确保开发人员能快速排查接口调用问题。

•     调用示例：提供完整的接口调用示例（如HTTP请求示例、代码调用示例），标注可修改的参数，方便开发人员参考调用。

•     注意事项：说明接口调用频率限制、权限要求、数据格式要求、版本兼容要求，以及接口调用后的后续操作（如数据同步、结果校验等）。

### 11.  环境要求编写规范

- 量化表述：所有要求需明确数值（如 CPU≥8 核、内存≥16G），禁止 “差不多”“足够” 等模糊词汇。
- 模块划分：按 “硬件 - 软件 - 网络 - 权限” 分类，结构清晰，便于 AI 提取关键信息。
- 版本明确：软件 / 依赖版本需标注 “≥X.X” 或具体兼容版本清单，严禁 “任意版本” 表述。
- 规则具体：防火墙、白名单、权限配置需给出明确配置规则（如 SELINUX 设置为 permissive）。

### 12.  部署/操作步骤编写规范

- 编号有序：按 “1. 2. 3.” 或 “1.1 1.2” 编号，不跳步、漏步，AI 可提取操作序列。
- 操作明确：每步仅含一个核心操作，配套命令、路径、用户，避免多操作混淆。
- 操作明确：每个步骤的输入输出、业务规则以及例外场景说明。
- 校验必加：关键步骤后必须添加校验方法与合格标准，确保操作生效。
- 差异标注：集群 / 单机、不同操作系统的操作差异明确标注，便于 AI 区分场景。

### 13.  安全与保密规范

- 敏感信息：密钥、密码、内网 IP 等标注【保密】，不明文展示，用 “[敏感信息]” 占位。
- 权限最小化：明确权限范围，避免过度授权（如部署账号仅分配必要权限）。
- 操作审计：重要操作（如配置修改、服务启停）建议记录操作日志，便于追溯。
- 端口管控：仅开放必要端口，禁用不必要端口，防火墙策略明确可查。

## 二、格式排版规范（Markdown通用）

| 元素     | 规范要求                                                     |
| -------- | ------------------------------------------------------------ |
| 页面设置 | A4纸张，页边距默认（Markdown渲染时自动适配）                 |
| 一级标题 | 格式：#1. 标题                                               |
| 二级标题 | 格式：`## X.X 标题`                                          |
| 三级标题 | 格式：`### X.X.X 标题`                                       |
| 四级标题 | 格式：`#### X.X.X.X 标题`                                    |
| 正文     | （Markdown用两个空格换行实现分段，行间距默认适配）           |
| 段落     | Markdown用`&emsp;&emsp;`实现），段落之间空1行                |
| 表格     | 边框完整（Markdown用`|`分隔列，`---`分隔表头），表头加粗，内容居中对齐，带编号 |
| 高亮提示 | 重要内容用`**加粗**`或HTML高亮标签（`<span style="background-color:yellow;">内容</span>`） |
| 图片     | 与上下文空1行，编号位于图片下方居中（例：`<center>图3-1 总体技术架构图</center>`），尺寸适配页面宽度 |
| 版本控制 | 标注版本号（V1.0、V2.0），记录修订人、日期、变更内容（建议用表格呈现） |
