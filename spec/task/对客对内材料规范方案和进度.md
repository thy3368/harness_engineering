# 对客材料规范建设——方案和进度汇报

## 一、建设目标

本次工作的目标，是围绕“设计能解决什么问题、适合什么场景、带来什么收益”这一统一要求，完善对客材料和对内产品材料的规范，并逐步通过 skill 落地，支撑材料编写、检查、修改和审核。

最终希望形成一套“规范、模板、checklist、skill”联动的建设方案，既能指导新材料编写，也能支持存量材料治理。

## 二、建设范围

当前已将建设对象初步分为三部分：

### 1. 对客材料
- 产品资料：技术白皮书、产品营销胶片、最佳实践
- 需求管理：需求规格、需求方案、需求排期清单、需求回复单、需求/方案沟通纪要
- 版本管理：操作手册、开发手册、运维手册、版本发布说明、版本测试报告、特性培训资料
- 技术支持管理：事件回复单、风险预警评估单、技术支持报告、问题分析报告

### 2. 对内材料
- 产品规划参考模板 / 填写示例
- 需求分析参考模板 / 填写示例
- 方案设计参考模板 / 填写示例
- 版本发布参考模板 / 填写示例
- 技术支持参考模板 / 填写示例

### 3. 规范建设内容
- 通用规范
- 各类模板
- 各类 checklist
- 后续的 skill 落地能力

## 三、整体方案

### 1. 先梳理材料范围和分类
先把材料清单盘清楚，并建立统一分类口径，避免后续规范建设只覆盖部分材料。

当前对需求相关材料，先按两大类管理：
- **对客需求类**：用于与客户沟通、澄清和确认需求
- **产品规格类**：用于内部定义和落地需求

### 2. 用统一口径收敛表达方式
后续重点材料统一按以下主线约束表达：
- 解决什么问题
- 适合什么场景
- 带来什么收益

通过这套口径，推动材料从“重功能、重技术”向“讲问题、讲场景、讲价值”转变。

### 3. 分层建设规范能力
按“规范—模板—checklist—skill”四层推进：

#### （1）规范层
明确各类文档的通用表达要求，以及不同材料的编写标准。

#### （2）模板层
将规范固化到模板中，降低编写门槛，提升一致性。

#### （3）checklist层
建立审核清单，用于材料自查、评审和准出控制。

#### （4）skill层
后续通过 skill 支撑：
- 新文档书写辅助
- 老文档排查与修订
- 准出自动检查
- 人工审核支持
