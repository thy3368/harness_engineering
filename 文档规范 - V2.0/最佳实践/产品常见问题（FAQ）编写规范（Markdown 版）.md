# 产品常见问题（FAQ）编写规范（Markdown 版）
## **1. 总则**

### **1.1** **编写目的**

统一问题描述口径、快速定位根因、给出可直接执行的解决方案，降低客户与实施/运维沟通成本。

### **1.2** **适用范围**

产品使用、部署、运维、接口调用、配置、升级、监控、应急故障等所有场景。

---

## **2. 标准章节结构（强制）**

### 2.1 问题概述（强制）

一句话说明问题现象，以及描述业务影响。

### 2.2 问题产生原因（如有）

说明问题产生的根因、触发条件等。

### 2.3 发现版本与环境（如有）

说明：问题出现的版本范围、操作系统、部署模式、数据库、运行环境等信息

| ---------------- | ----------------------------- |

| 问题存在版本范围 |                               |
| 操作系统         |                               |
| 部署模式         | □ 单机 □ 集群 □ 私有化 □ 云端 |
| 数据库版本       |                               |
| JDK/运行环境     |                               |
| 网络环境         | □ 内网 □ 外网 □ 跨网 □ 隔离区 |
| 特殊环境         |                               |

### 2.4 影响范围（如有）

说明问题对应的功能、业务等影响，以及影响程度。

| 范围类型 | 影响内容                 | 影响程度                         |
| -------- | ------------------------ | -------------------------------- |
| 功能影响 | ________________________ | □ 轻微 □ 中等 □ 严重             |
| 用户影响 | ________________________ | □ 部分用户 □ 全部用户            |
| 数据影响 | ________________________ | □ 无 □ 部分异常 □ 数据不一致     |
| 业务影响 | ________________________ | □ 可继续 □ 部分中断 □ 完全不可用 |
| 性能影响 | ________________________ | □ 无 □ 变慢 □ 阻塞               |

---

### 2.5 复现步骤（如有）

说明问题复现的步骤，以及最后的表象。

### 2.6 解决方案（强制：可直接执行）

说明问题的解决方案以及解决类型、解决方案的详细操作步骤，并提供对应的命令/配置/SQL/示例代码等信息

#### 2.6.1 解决方案类型（按需）
□ 临时规避 □ 配置修复 □ 代码修复 □ 重启修复 □ 升级修复 □ 数据修复

#### 2.6.2 详细操作步骤

要求：按 “步骤编号 - 操作内容 -步骤效果” 格式编写，步骤有序，无跳步、漏步，每步校验可落地，便于 AI 提取操作流程。

#### 2.6.3 命令/配置/SQL（必须完整）

```bash

```

```yaml

```

```sql
-- 粘贴SQL
```

#### 2.6.4 解决方案效果

要求：说明解决方案对应的效果，以及验证结果。

#### 2.7.1 排查顺序

要求：提供问题排查顺序，检查日志路径、检查关键字信息、检查配置项信息、检查数据库/中间件状态信息等

#### 2.7.2 排查命令


### 2.8 解决版本（如有）

如是某个版本才支持的功能，提供升级版本以及升级注意事项。

### 2.9 关联信息（可选）

#### 2.9.1 关联问题
如跟其他问题关联，提供对应问题关联编号

#### 2.9.2 相关接口/配置
提供问题对应的接口、配置信息

#### 2.9.3 相关文档

提供问题对应的文档信息，例如操作手册、开发手册、运维手册、最佳实践等

## 3. 编写规范（强制执行）

- **问题标题必须精准**，禁止模糊描述（如“系统报错”“打不开”）  
- **原因必须写根因**，不写表面现象  
- **步骤必须可复现**，一步一步写清  
- **解决方案必须可直接复制执行**，无需额外理解  
- **环境、版本必须明确**，不写“可能”“大概”  
- **影响范围必须量化**：部分/全部、可继续/不可用  
- 所有命令、配置、SQL 必须放入代码块  
- 同一类问题必须统一口径
