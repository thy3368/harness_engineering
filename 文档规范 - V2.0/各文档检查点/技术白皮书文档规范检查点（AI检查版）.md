# 技术白皮书文档规范检查点（AI检查版）
| 检查维度     | 检查项                                                     | 检验规则                                                     | 是否强制 |
| ------------ | ---------------------------------------------------------- | ------------------------------------------------------------ | -------- |
| 内容逻辑     | 内容无前后矛盾，逻辑连贯                                   | 全文档核心要求，需确保各章节表述一致、推导合理               | 强制     |
| 架构表述     | 架构图与文字描述一致，无歧义                               | 架构图需匹配分层说明、部署架构等文字内容，图例/箭头/说明完整无偏差 | 强制     |
| 技术栈准确性 | 技术栈准确、版本号统一无冲突                               | JDK、框架、中间件等技术栈名称及版本号需全程统一，无错误或冲突表述 | 强制     |
| 价值点表述   | 价值点可量化、易理解，无空泛表述                           | 核心价值、技术能力价值等需落地（如“性能提升30%”），避免“高效、优秀”等空泛词 | 强制     |
| 合规安全     | 符合信创、合规、安全相关要求                               | 需覆盖信创全栈适配、等保/密评、数据/传输/存储安全等合规要求  | 强制     |
| 格式规范     | 无错别字、格式错乱、图表缺失编号问题                       | 基础格式要求，包含文字纠错、Markdown格式统一、图表有序编号   | 强制     |
| 场景完整性   | 典型应用场景包含实施部署相关的环境要求、部署模式等内容     | 仅针对涉及实施部署的解决方案类场景，无部署环节的产品可忽略   | 可选     |
| 生态能力描述 | 开放生态与集成能力模块完整覆盖OAuth2.0、标准化接口等内容   | 非开放型产品可根据实际场景精简，仅保留核心集成能力表述       | 可选     |
| 版本修订记录 | 版本修订记录完整填写（修订内容、日期、更新人）             | 初稿可仅标注基础信息，后续版本迭代需补充完整                 | 可选     |
| 演进规划     | 总结与展望章节包含清晰的演进路线、未来规划                 | 早期版本白皮书可仅聚焦当前价值，成熟产品建议补充             | 可选     |
| 技术特性扩展 | 关键技术特性按需补充灵动高效、可组合、技术自治等适配性表述 | 可根据产品类型（平台/中台/信创类）调整，匹配核心特性即可     | 可选     |
| 差异优势对比 | 产品概述中明确与同类产品的差异优势                         | 对内使用的白皮书可简化，对外输出建议完整表述                 | 可选     |

### 补充说明
1. **强制项**：为白皮书核心质量底线，未达标需整改后方可定稿，直接影响文档权威性与可用性；
2. **可选项**：需结合白皮书使用场景（对内/对外）、产品成熟度、目标受众灵活调整，核心原则为“贴合产品实际，无冗余表述”；
3. 所有检查项需基于《产品技术白皮书编写规范》的目录结构与核心要求执行，可选项的删减不影响强制项的完整性。
