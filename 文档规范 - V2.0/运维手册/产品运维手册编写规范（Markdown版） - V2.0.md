# 产品运维手册编写规范（Markdown版）-V2.0

## 1. 总则

### 1.1 编写目的

规范产品部署手册的编写格式、内容结构、表述标准，统一部署（新环境）、升级（现有版本）、巡检、应急诊断、环境迁移等全流程的撰写口径，让部署人员、运维人员、实施人员能快速读懂、按步骤操作，降低部署 / 升级出错率，缩短操作周期，保障产品全生命周期稳定、合规、可正常运行，实现标准化运维。

### 1.2 适用范围

- 覆盖产品：公司所有软件产品、硬件配套产品；
- 覆盖场景：单机部署、集群部署、云端部署、本地化部署（新环境安装部署）；现有版本增量 / 全量 / 灰度升级；核心链路 / 交易巡检；开市 / 闭市等日常运维；数据库 / 资产等环境迁移；应急诊断处置；
- 覆盖流程：环境准备、安装配置、升级操作、巡检校验、应急处置、环境迁移、资源管理；
- 适用人员：手册编写、审核、校对、使用全环节人员。

### 1.3 核心编写原则

- **可操作性**：步骤、指令、配置直白易懂，无模糊表述，可直接执行，无需额外猜测；
- **精准性**：配置项参数、路径、命令、阈值、版本号与产品实际要求完全一致，无错写、漏写、乱标；
- **完整性**：覆盖部署、升级、巡检、运维、应急、迁移全流程，不省略前置条件、中间操作、后置校验，重点补齐配置项、联动检测、异常处理环节；
- **规范性**：格式、编号、术语、命令风格统一，重点突出，层级清晰，便于 AI 识别与检索；
- **安全性**：明确权限配置、敏感信息处理、端口管控、防火墙规则，保障运维全流程安全；
- **场景化**：按部署方案、升级类型、巡检场景等维度拆分内容，贴合实际运维场景。

### 3.5 联动配置检测编写规范

- 结构化呈现：按 “检测前提 - 检测流程 - 检测项 - 补充要求” 结构编写，便于 AI 提取逻辑；
- 表格统一：检测项表格字段固定，检测方法、合格标准、修复方案需具体可执行，无模糊表述；
- 命令完整：所有检测命令需给出完整参数、执行路径、用户，可直接复制运行；
- 分级处理：巡检异常按 “轻微（不影响业务）- 中度（部分功能异常）- 重度（业务中断）” 分级，对应不同处置优先级；
- 升级后的联动检测需新增 “版本兼容性检测项”，巡检环节的联动检测需按核心链路 / 交易场景拆分；

### 3.6 安全与保密规范

- 敏感信息：密钥、密码、内网 IP 等标注【保密】，不明文展示，用 “[敏感信息]” 占位；
- 权限最小化：明确权限范围，避免过度授权（如部署账号仅分配必要权限）；
- 操作审计：重要操作（如配置修改、服务启停、升级、环境迁移、应急处置）对应关键操作需记录操作人、操作时间、操作内容，日志路径明确可查）建议记录操作日志，便于追溯；
- 端口管控：仅开放必要端口，禁用不必要端口，防火墙策略明确可查；
- 资源管理中的密码、证书需严格按【保密】标注，环境迁移过程中的敏感数据传输需明确加密方式。

### 3.7 场景化内容编写要求

- 部署方案：每个方案需独立成章节，环境要求、步骤、表格需适配场景，无通用化模糊表述；
- 升级流程：增量 / 全量 / 灰度升级需明确区分操作差异，回滚机制需具体可执行；
- 巡检内容：核心链路 / 交易巡检需按实际业务场景拆分，指标可量化、可检测；
- 日常运维：开市 / 闭市等操作需清单化，明确 “做什么、谁来做、什么时候做、做错了怎么办”。
