# 产品用户操作手册编写规范（Markdown 版）

适用于：平台产品包含界面交互相关的用户操作手册

================================================================================

## 1. 总则

### 1.1 编写目的

规范产品用户操作手册的编写格式、内容结构、图文排版，保证手册内容清晰易懂、格式统一、指引准确，帮助用户快速上手操作产品，降低使用门槛，减少咨询与售后成本。

### 1.2 适用范围

本规范适用于公司所有面向终端用户、管理员、运维人员的产品用户操作手册编写，手册包含产品界面展示、步骤指引、功能说明、常见问题等内容。

### 1.3 编写原则

- 通俗易懂：用语直白简洁，避免专业术语堆砌，术语首次出现需标注释义，杜绝口语化、模糊化表述。
- 图文并茂：关键操作、核心界面必须配图，图随文走，步骤与截图一一对应，指引清晰无歧义。
- 准确完整：内容与产品实际功能、界面完全一致，不漏步骤、不写错路径，覆盖常用功能与核心场景。
- 结构清晰：章节层级分明，逻辑连贯，方便用户快速检索、定位所需内容。
- 统一规范：全文格式、字体、编号、图标、术语保持一致。

## 2. 标准章节结构（强制）

1. 修订记录页：记录版本号、修订日期、修订内容、修订人、审核人。
2. 前言（概述）：说明产品用途、核心功能、适用用户、手册阅读建议、使用须知。
3. 产品术语说明：按业务模块分类，明确术语定义、用途及使用场景。
4. 假定约束：说明文档的适用范围、适用对象、环境/条件/数据等前提条件。
5. 产品总体介绍：整体业务说明（业务架构图+说明）、整体界面说明（界面风格、布局）、系统完整功能树、系统角色功能矩阵、整体流程与角色说明等。
6. 各功能模块操作指引（核心）：按模块拆分，含功能可解决的客户问题、功能说明以及规格、前置条件、操作入口、步骤（每个步骤的输入输出、业务规则以及例外场景说明）、图示（需包含说明）、注意事项。
6. 版本兼容说明：说明对应功能支持的版本，可合入各功能模块的注意事项
8. 附录：包含权限说明、快捷键、联系方式等。

## 3.审核与交付规范

1. 核对内容与产品实际功能、界面一致性，校验步骤、图文匹配度。
2. 检查格式、编号、排版是否符合规范，修正错别字、语病。
3. 交由产品负责人、测试人员审核，确认无误后定稿归档。
4. 产品版本迭代后，同步修订手册内容，更新版本号与修订记录。
