# AI驱动的软件研发体系架构图（全景视图）

从基础设施到治理体系，构建企业级AI驱动的软件研发工程体系，分为五层（2026.6）

## 第1层：基础设施层（Infrastructure）,AI研发的底层支撑

### 1. 模型(项目级统一) 
  - DeepSeek、GLM、Mimo  
  - MiniMax、Kimi、QWen     
  - GPT、Claude  

  **原则：** 项目级统一，Coding Plan优先，DeepSeek充值兜底

### 2. Agent平台（项目级统一） 
  - CLI：Claude Code、OpenCode、ZCode
  - IDE：Trae、CodeBuddy、Curosr  
  - Work：WorkBuddy...

  **原则：** 项目级统一，vscode+cli 或 模型厂商IDE（注意关闭数据收集选项）

### 3. 产品资产库（细化到模块，以便保鲜）  
  - 产品资产库（需求、设计、代码）    
  - 产品AI流程资产库（Skills、模板、脚本）

  **原则：** 最小资产粒度到功能点/单一源码文件对应，超千行源码建二级引用；产品与研发岗按各自维度建引用文件；文本类知识库管理参考[谷歌OKF标准](okf_v0.1核心规则解读.html); 产品AI流程资产属于如何实现系统的设计文档（参见第三层要求）；

OKF规范三个设计原则：
- 原子化知识单元：每个知识项（如一张数据表、一个业务指标）独立成一个Markdown文件，形成可管理的“知识原子”。
- 生产者与消费者解耦：无论是人工编写还是AI自动生成，只要遵循格式，任何工具都能消费这些知识，反之亦然。
- 渐进式暴露：通过index.md入口文件，允许智能体或用户先了解全局结构，再按需深入细节，避免信息过载。

### 4. 工具连接能力（公共Skill/CLI/API/MCP）  
  - Git/SVN  
  - 效能平台
  - 开发平台（HEP、常规开发环境）
  - 大模型网关

  **原则：** 公司级统一，定制桌面云内Agent依赖环境（python、nodejs、powershell）；

### 其他通用支撑能力（公司级统一）  
  本地化部署 /容器化部署 / 网络安全 / 存储 / 计算 / 监控  

## 第2层：Agent执行层，多Agent协同完成研发任务

### Agent 类型与职责
  - Req Agent：需求分析、需求管理  
  - Design Agent：架构设计、概设详设、方案评估  
  - Coding Agent：代码生成、代码重构、Bug 修复  
  - Test Agent：测试分析、用例生成、测试方案、测试执行  
  - Review Agent：需求评审、设计评审、代码评审、测试评审
  - PM Agent：范围、质量、进度、成本、沟通、风险...报告与度量
  - QA Agent：规范审视、质量分析

**注意事项：**
- 各类Agent输入依赖产品资产库，通过合适的功能地图连接有效范围的资产，使Agent上下文大小受控；
- 各类Agent输出明确，可统一参考模板；
- 各类Agent的处理流程，一般可采用skill表示（第三层，给出流程的详细定义）；

### Agent编排协同原则  
  - Agent间任务分发与状态管理通过公司提供基础设施，强制阶段成果持续化
  - Agent上下文隔离与共享，特别是审核验证类Agent要独立
  - SubAgent之间协同机制根据场景编排需要定，建议中间结果要持久化
  - SDD优先使用Agent平台原生已提供的协同机制

## 第3层：流程层（Development Process），设计由AI主导人工审核的研发全流程

结合产品业务架构、实现架构，分类细化制定：
**所有流程本质上是指导AI人机协作完成系统实现，属于设计资产，均需入配置库版本化管理**
### AI需求与规划  
   需求收集，补全或关联背景信息
   需求拆解，业务架构影响，相似需求分析  
   方案规划，影响的具体版本、模块、工时预估 

### AI设计与规划  
   架构设计，通过功能地图补全或关联背景信息
   方案生成，影响范围、测试点、工时预估
   技术选型  

### AI编码实现  
   代码生成，提供上下文信息通过，调用工具或大模型直出生成  
   重构优化，大模型分析生成重构工具 
   文档生成，同步更新文档
   CI/CD,持续迭代  

### AI测试与验证  
   测试生成，测试用例、测试数据生成  
   自动化测试，回归测试，分支同步测试；接口、前端自动化测试  
   缺陷分析  

### AI预审，人工验证与确认
   需求、设计Review  
   代码Review  
   测试准出Review
  
### 三类核心支持能力：
  - Intent Engineering（意图工程｜清晰表达要什么What）  
  - Loop Engineering（Loop工程｜如何实现How）  
  - Verification Engineering（验证工程｜自动化验证制质量）

**原则：** 与公司效能等流程结合，满足上层项目管理要求；预埋度量点，支持多维度人效分析；
