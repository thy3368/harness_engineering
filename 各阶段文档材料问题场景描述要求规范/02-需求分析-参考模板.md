# 需求分析相关文档参考模板

> **模板编号**：TPL-RA-002
> **适用环节**：需求分析
> **质量要求**：L2-良好（重点特性L3）
> **引用规范**：《产品价值表达统一规范》（SPEC-PV-001）
> **模板基线**：基于BData需求规格说明书模板扩展，新增"收益分析"和"场景边界"独立字段

## 涉及文档类型与模板使用说明

| 文档类型 | 说明 | 使用方式 | 侧重点 |
|----------|------|----------|--------|
| **需求规格说明书** | 完整的需求分析文档 | 使用本模板第1-11章完整内容 | 全面覆盖价值表达、功能/非功能需求、验收标准 |
| **需求回复单** | 向需求方回复处理意见的简表 | 使用附录中的子模板 | 三要素各一句话 |
| **排期确认单** | 确认实施排期的决策文档 | 使用附录中的子模板 | 场景和收益摘要，便于决策者判断优先级 |

> 需求规格说明书是核心文档，回复单和确认单从中提取关键信息。三份文档中的价值表达口径应保持一致。

## 4. 需求描述（黄金圈法则）

> Why -> How -> What，从内向外、从抽象到具体。

### 3.1 Why - 业务问题

【回答"为什么要做这个需求"，与 2.1 节呼应但更聚焦业务层面。】

### 3.2 How - 解决思路

【回答"打算怎么解决"，描述方案核心理念和关键路径，不涉及技术细节。】

### 3.3 What - 具体需求

【回答"具体要做什么"，列出本次需求包含的功能项。】

## 5. 需求目标分析

### 4.1 SMART分析

| SMART维度                    | 内容                                                         |
| ---------------------------- | ------------------------------------------------------------ |
| S - Specific         | 【具体要实现什么功能/达到什么效果？】 |
| M - Measurable     | 【如何衡量是否达成？可量化指标。】   |
| A - Achievable     | 【技术和资源条件是否可行？】 |
| R - Relevant       | 【与产品战略和客户核心诉求的关联？】     |
| T - Time-bound     | 【计划时间范围和关键里程碑？】 |

### 4.2 KANO分类

| 分类                         | 判断依据                                                     | 本需求判定           |
| ---------------------------- | ------------------------------------------------------------ | -------------------- |
| 基本型（Must-be）            | 不具备时用户强烈不满，具备时认为理所当然                 | 【是/否，理由】 |
| 期望型（One-dimensional）    | 具备时满意度线性提升                     | 【是/否，理由】 |
| 兴奋型（Attractive）         | 不具备时无感，具备时惊喜                             | 【是/否，理由】 |
| 无差异型（Indifferent）      | 具备与否对满意度无显著影响                               | 【是/否，理由】 |
| 反向型（Reverse）            | 具备时反而导致不满                                       | 【是/否，理由】 |

**KANO分类结论**：【最终判定及理由】
