# 版本发布环节 - 参考模板

> **定位**：版本发布是面向业务部门的"最后一公里"，所有材料必须用业务语言。
>
> **涉及材料**：Release Notes、用户手册、特性培训材料
>
> **质量要求**：Release Notes L2，用户手册/培训材料 L3
>
> **引用规范**：《产品价值表达统一规范》（SPEC-PV-001）

---

## 子模板A：Release Notes 模板

```markdown
# [产品名称] V[版本号] 发布说明

## 版本概览

| 项目     | 内容                                       |
| -------- | ------------------------------------------ |
| 版本号   | 【完整版本号，如 V3.2.0】              |
| 发布日期 | 【如 2026-03-29】            |
| 适用环境 | 【部署环境和操作系统等】     |

## 新增特性

### 特性1：【特性名称】

| 要素         | 内容                                                         |
| ------------ | ------------------------------------------------------------ |
| 解决什么问题 | 【必填：用业务语言描述当前痛点】 |
| 适用场景     | 【必填：谁在什么情况下使用】   |
| 收益/效果    | 【必填：改善效果，尽量量化】   |
| 使用方式     | 【简要操作指引或文档链接】                       |
| 注意事项     | 【升级影响、兼容性、使用限制等】       |

【根据特性数量复制上述条目】

## 优化改进

### 改进1：【改进名称】

| 要素         | 内容                                                         |
| ------------ | ------------------------------------------------------------ |
| 解决什么问题 | 【必填：之前的不便或低效之处】               |

| 使用方式     | 【如何使用改进后的功能】                             |
```

## 子模板B：用户手册章节规范

```markdown
# [功能名称] 用户手册

## 1. 功能概述

### 1.1 场景说明
【先说明本功能解决什么问题、适用什么场景，再讲操作步骤。
  从用户视角出发，描述"没有这个功能时的困境"和"有了之后的改善"。】

### 1.2 使用边界
【什么情况适用、什么情况不适用：

**步骤1：【步骤标题】**

## 5. 常见问题

A：【解答，必要时给出操作指引】

## 6. 相关功能
```

## 子模板C：特性培训材料大纲

```markdown
# [特性名称] 培训材料

## 培训信息

| 项目     | 内容                                           |
| -------- | ---------------------------------------------- |
| 培训时长 | 【如 60 分钟】                       |
| 目标受众 | 【业务人员/运维人员/架构师等】                 |
| 前置知识 | 【需要提前了解的背景】                     |
| 培训目标 | 【培训后学员能做到什么】                 |

## 1. 业务问题引入（约10%时间）

【从业务痛点切入，不直接讲功能。
  描述一个真实的业务困境案例，让听众产生共鸣，引出问题的核心矛盾，自然过渡到解决方案。】

## 2. 场景演示（约30%时间）

【用真实业务场景演示，不是功能菜单导览。
  设计 2-3 个场景，每个包含：背景 → 操作演示 → 效果展示。
  对照"没有此功能时"和"使用后"的差异。

  场景1：【场景名称】
  - 背景：【业务背景】
  - 演示要点：【关键操作】
  - 效果对比：【使用前后差异】

  场景2：【场景名称】
  - 背景 / 演示要点 / 效果对比】

## 3. 操作指导（约30%时间）

【step-by-step 操作指导，配截图/录屏说明。
  标注容易出错的地方，设置动手练习环节。

  动手练习：
  - 练习题目：【独立完成的任务】
  - 预期结果：【完成后应看到的效果】
  - 参考时间：【建议完成时间】】

## 4. 收益总结（约10%时间）

【回顾解决了什么问题、带来什么收益。
  量化收益数据，给出"下一步行动建议"——学员回去后可以做什么。】

## 5. 复杂场景案例（约20%时间）

【进阶案例，面向架构师/高阶用户。
  涉及架构级思考，有一定复杂度（多系统协同、特殊约束等），
  引导学员思考方案选型和权衡取舍。

  案例1：【复杂场景名称】
  - 业务背景 / 挑战 / 方案设计 / 经验总结

  案例2：【复杂场景名称】
  - 业务背景 / 挑战 / 方案设计 / 经验总结】
```

## 模板使用说明

| 材料类型 | 质量等级 | 核心检查点                                                   |
| -------- | -------- | ------------------------------------------------------------ |
| Release Notes | L2  | 三要素完整，无技术术语，业务部门可直接阅读 |
| 用户手册     | L3  | 场景先行、操作步骤完整、参数说明清晰、FAQ 覆盖常见问题       |
| 培训材料     | L3  | 从痛点切入、场景演示为主、包含进阶案例   |

**关键原则**：
1. **业务语言优先**：面向用户的材料不出现纯技术术语，必须翻译为业务语言
2. **三要素表达**：每个特性都要回答"解决什么问题、适用什么场景、带来什么收益"
3. **场景驱动**：先讲"为什么"再讲"怎么做"
4. **可操作性**：操作指引必须 step-by-step，照做即可完成
