# DFX评分规则

本文件是 AI 设计评分中 DFX 质量属性专项规则的 SSOT，覆盖性能、可靠性、安全、兼容性、可维护性、可观测性六类规则。通用评分模型、权重、等级、阻断项和计算公式仍以 [评分规则体系-v2.md](评分规则体系-v2.md) 为准；四类阶段规则只负责说明阶段证据如何消费本文件规则。

## 规则元信息

| 项目 | 内容 |
|---|---|
| 适用对象 | 技术预分析、架构设计、概要设计、详细设计中的 DFX 质量属性评分 |
| 规则版本 | v1.0 |
| 编号前缀 | `DFX-*` |
| 规则范围 | 性能、可靠性、安全、兼容性、可维护性、可观测性 |

## 阶段适配口径

| 阶段 | 覆盖判定口径 |
|---|---|
| 技术预分析 | 检查是否识别 DFX 风险、影响对象、初步验证方式，并提出后续设计要求；不要求完整落地方案。 |
| 架构设计 | 检查是否落实到架构组件、链路、机制、部署或运行约束，并说明架构级验证方式。 |
| 概要设计 | 检查是否落实到模块、接口、数据、配置、任务或工程结构方案，并说明模块级验证方式。 |
| 详细设计 | 检查是否落实到代码级路径、分支异常、测试点、灰度、回滚、日志、指标、Trace 和告警。 |

## 通用评分口径

| 分值 | 判定标准 |
|---:|---|
| 5 | 命中的 DFX 规则均给出触发对象、设计措施、必须证据和验证方式，且符合当前阶段粒度。 |
| 3 | 已覆盖主要 DFX 风险，但触发对象、设计措施、验证方式或阶段粒度存在明显缺口。 |
| 0 | 命中 DFX 触发条件但未分析，或只有原则性口号，无法支撑评审。 |

## P0/P1 阻断口径

| 严重度 | 判定口径 |
|---|---|
| P0 | 命中安全敏感、核心链路可靠性、接口兼容、数据或生产发布高风险场景，且完全缺少对应 DFX 分析；应套用通用阻断项或阶段对象级阻断项。 |
| P1 | 已识别 DFX 场景但证据不足、缺少验证方式、缺少影响对象或未达到当前阶段粒度；应限制 `E. DFX质量属性覆盖` 维度等级。 |

## 样例判定口径

- 接口变更但无兼容性分析：命中 `DFX-COMP-*`，同时可命中 `COMMON-BLOCK-07`；`E. DFX质量属性覆盖` 和相关接口/影响范围维度不得按完整覆盖评分。
- 核心链路但无可靠性设计：命中 `DFX-REL-*`，同时可命中 `COMMON-BLOCK-06`；必须要求补充超时、重试、幂等、降级、补偿或失败恢复证据。
- 技术预分析已识别 DFX 风险并给出后续设计要求：可按技术预分析阶段视为覆盖；架构、概要、详细阶段必须提供符合对应阶段粒度的落地证据。

## DFX-PERF 性能

| 规则编号 | 规则项 |
|---|---|
| `DFX-PERF-01` | 容量与负载评估 |
| `DFX-PERF-02` | 查询、批量、渲染或计算复杂度控制 |
| `DFX-PERF-03` | 索引、缓存、限流、分页或异步化措施 |
| `DFX-PERF-04` | 压测、基准验证或性能回归验证 |

- 触发条件：涉及高频调用、大数据量、批处理、查询、渲染、计算密集逻辑、核心链路容量扩展。
- 必须证据：容量/QPS/数据量估算，复杂度或瓶颈分析，索引/缓存/限流等措施，压测或基准验证方式。
- 5分判定：关键性能风险均有对象、指标、设计措施和验证方式，指标与业务量级匹配。
- 3分判定：识别主要性能风险，但容量估算、瓶颈分析或验证方式不足。
- 0分判定：命中性能场景但无性能分析。
- P0/P1阻断口径：核心链路高并发或大数据量场景无任何容量和验证说明为 P1；可能造成生产不可用且无缓解措施时按 P0 处理。
- 常见缺口：只写“性能可接受”；无 QPS/数据量；无索引说明；缓存无失效策略；无压测口径。
- 推荐验证方式：压测、基准测试、慢 SQL 分析、执行计划、容量模型、性能回归对比。

## DFX-REL 可靠性

| 规则编号 | 规则项 |
|---|---|
| `DFX-REL-01` | 超时、重试、熔断和降级 |
| `DFX-REL-02` | 幂等、补偿和失败恢复 |
| `DFX-REL-03` | 异步任务、批处理和长事务可靠性 |
| `DFX-REL-04` | 故障演练、异常测试和恢复验证 |

- 触发条件：涉及核心链路、远程调用、异步任务、批处理、长事务、多实例协作、失败恢复。
- 必须证据：超时重试策略，幂等键或去重方案，熔断降级条件，补偿/恢复流程，异常验证方式。
- 5分判定：正常路径、异常路径、恢复路径和验证方式完整，且与影响对象对应。
- 3分判定：覆盖核心失败场景，但超时、幂等、补偿或验证存在缺口。
- 0分判定：命中可靠性场景但无可靠性设计。
- P0/P1阻断口径：核心链路无可靠性设计命中 `COMMON-BLOCK-06`；异步任务无幂等或失败恢复通常为 P1。
- 常见缺口：只写“失败后重试”；无最大重试次数；无幂等边界；补偿任务无人工介入入口。
- 推荐验证方式：异常注入、超时重试测试、重复请求测试、任务积压测试、恢复演练。

## DFX-SEC 安全

| 规则编号 | 规则项 |
|---|---|
| `DFX-SEC-01` | 鉴权、权限边界和最小权限 |
| `DFX-SEC-02` | 租户隔离、数据权限和越权防护 |
| `DFX-SEC-03` | 敏感数据、加密、脱敏和密钥管理 |
| `DFX-SEC-04` | 外部访问、攻击面和安全审计 |

- 触发条件：涉及登录、鉴权、权限、租户、敏感数据、加密、外部访问、审计、跨系统授权。
- 必须证据：权限模型和校验点，租户/数据边界，敏感数据处理方式，加密或脱敏方案，审计留痕和回滚影响。
- 5分判定：权限边界、数据保护、审计和验证完整，关键校验点可定位。
- 3分判定：覆盖主要安全风险，但权限校验点、租户隔离或审计证据不足。
- 0分判定：命中安全场景但无安全设计。
- P0/P1阻断口径：安全敏感场景无安全设计命中 `COMMON-BLOCK-05`；越权、敏感数据泄露或外部访问无边界说明按 P0 处理。
- 常见缺口：只写“按现有权限”；无资源粒度；无租户隔离；敏感字段未脱敏；缺少审计事件。
- 推荐验证方式：权限矩阵评审、越权测试、敏感数据扫描、接口鉴权测试、审计日志核查。

## DFX-COMP 兼容性

| 规则编号 | 规则项 |
|---|---|
| `DFX-COMP-01` | 调用方影响和契约兼容 |
| `DFX-COMP-02` | 版本兼容、默认值和配置迁移 |
| `DFX-COMP-03` | 灰度迁移、双写/双读和回滚兼容 |
| `DFX-COMP-04` | 废弃策略、通知和兼容验证 |

- 触发条件：涉及接口、协议、消息、事件、数据结构、配置默认值、对外契约或存量数据变更。
- 必须证据：调用方清单，版本或字段兼容策略，默认值和迁移方式，灰度/双写/双读/回滚方案，废弃通知和验证方式。
- 5分判定：存量调用方、版本迁移、灰度回滚和验证均完整。
- 3分判定：说明了兼容策略，但调用方、默认值、迁移或回滚证据不足。
- 0分判定：命中兼容性场景但无兼容性分析。
- P0/P1阻断口径：接口变更无兼容性分析命中 `COMMON-BLOCK-07`；破坏存量调用且无迁移策略按 P0 处理。
- 常见缺口：无调用方清单；字段新增无默认值；接口删除无废弃期；灰度期间读写路径未说明。
- 推荐验证方式：契约测试、兼容回归、灰度验证、双写双读校验、存量数据迁移演练。

## DFX-MAINT 可维护性

| 规则编号 | 规则项 |
|---|---|
| `DFX-MAINT-01` | 模块边界、职责划分和依赖方向 |
| `DFX-MAINT-02` | 配置化、扩展点和规则引用 |
| `DFX-MAINT-03` | 复杂度控制、重复逻辑和演进成本 |
| `DFX-MAINT-04` | 资产治理、责任归属和后续维护 |

- 触发条件：涉及新增模块、跨层依赖、公共能力、规则引擎、配置化扩展、复杂流程、长期演进能力。
- 必须证据：模块职责边界，依赖方向，配置项或扩展点设计，复杂度控制方式，规则引用和责任归属。
- 5分判定：边界清晰、依赖合理、扩展点可控、规则和资产治理闭环完整。
- 3分判定：模块方案可理解，但依赖、扩展点、复杂度或治理证据不足。
- 0分判定：命中可维护性场景但无可维护性分析。
- P0/P1阻断口径：职责边界不清导致无法拆分或长期维护风险显著时为 P1；架构边界错误导致方案不可实施时按阶段阻断项处理。
- 常见缺口：模块职责重叠；跨层调用未解释；配置项无作用域；扩展点无限开放；未引用适用规则。
- 推荐验证方式：架构评审、依赖扫描、复杂度评估、配置校验、规则清单核对。

## DFX-OBS 可观测性

| 规则编号 | 规则项 |
|---|---|
| `DFX-OBS-01` | 日志、指标和 Trace |
| `DFX-OBS-02` | 告警、看板和排障入口 |
| `DFX-OBS-03` | 业务审计和关键事件留痕 |
| `DFX-OBS-04` | 监控验证和故障定位演练 |

- 触发条件：涉及生产运行、故障定位、核心链路、任务调度、外部调用、权限审计、发布变更。
- 必须证据：关键日志字段，指标名称或统计口径，Trace 贯通点，告警条件，看板或排障入口，业务审计事件和验证方式。
- 5分判定：日志、指标、Trace、告警、看板、排障入口和审计与影响对象对应。
- 3分判定：有日志或监控说明，但指标、Trace、告警阈值、看板或排障入口不足。
- 0分判定：命中可观测性场景但无可观测性设计。
- P0/P1阻断口径：核心链路或生产发布变更无任何监控告警通常为 P1；无法定位重大生产故障且无补充手段时按 P0 风险处理。
- 常见缺口：只写“打印日志”；无 requestId/traceId；无指标口径；告警无阈值；无业务审计。
- 推荐验证方式：日志字段核查、指标上报测试、Trace 串联测试、告警演练、看板验收、审计记录核查。
