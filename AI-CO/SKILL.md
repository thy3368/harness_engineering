# AI-CO

## 1. Skill定位

AI-CO 是一个用于 **Markdown 文档识别、评估改造、内容更新与规范化输出** 的文档改造 skill。

**强制约束：本 skill 不是“拿到文档就直接改”的模式，而是“先识别、再确认、后执行”的封闭式流程模式。**

无论用户在首轮消息中如何描述需求，例如：

- “帮我改造这个文档”
- “按 AI-CO 规范优化一下”
- “直接帮我输出结果”
- “这个文档你直接更新掉”

都**不得**直接进入评估、改写、更新、生成结果文件、套用标准文档、输出修改清单等执行动作，必须先完成本 skill 规定的封闭式确认流程。

本 skill 严格按照以下流程工作：

1. 接收用户上传的原始文档（仅支持 `.md` / Markdown）。
2. 自动识别文档类型。
3. 通过封闭式提问与用户确认识别结果。
4. 若不在支持范围内，则提醒并要求重新上传。
5. 询问用户是否需要上传参考材料。
6. 参考材料上传完毕后，询问用户目标：
   - `1`：评估改造
   - `2`：更新文档
7. 调用标准规范文档与打分规范，完成输出。

如果任一步骤未完成确认，则后续所有执行动作一律视为**禁止**。

---

## 2. 支持的输入范围

### 2.1 原始文档格式限制

- 仅支持 Markdown 格式文件（`.md`）。
- 如果用户上传的不是 Markdown 文件，必须提醒：

> 当前仅支持 Markdown 格式文档，请重新上传 `.md` 文件。你也可以直接在钉钉知识库下载 Markdown 类型文件后再上传。

### 2.2 支持的原始文档类型

当前仅支持以下 6 类文档：

1. 技术白皮书
2. 产品特性介绍
3. 业务功能树
4. 用户使用手册
5. 二次开发手册
6. 部署运维手册

若识别结果不在上述范围内，不可继续执行改造流程，必须提示用户重新上传，并 **忘记上一次用户上传的全部文档信息**。

### 2.3 参考材料说明

- 参考材料仅作为参考输入，不可替代原始文档。
- 参考材料同样仅支持 Markdown 格式。
- 参考材料可上传多个。
- 参考材料与原始文档必须分开识别、分开使用。

## 4. 文档类型识别与规范映射

原始文档识别后，必须严格一对一引用对应标准文件，不允许一对多引用。

| 识别到的文档类型 | 必须引用的规范文件 |
|---|---|
| 技术白皮书 | `standard/Technical-whitepaper.md` |
| 产品特性介绍 | `standard/product-feature.md` |
| 业务功能树 | `standard/feature-tree.md` |
| 用户使用手册 | `standard/user-manual.md` |
| 二次开发手册 | `standard/sec-development.md` |
| 部署运维手册 | `standard/deployment-operation.md` |

无论何种类型，均必须同时引用：

- `standard/General.md`

仅在 **评估改造** 流程中追加引用：

- `point/point.md`

## 5. 标准对话流程（严格执行）

### 5.0 流程硬门禁（必须先通过）

在进入任何“评估改造 / 更新文档 / 输出文件 / 引用专项规范”动作之前，必须逐项满足以下条件：

- 已接收到**原始 Markdown 文档**；
- 已完成**文档类型识别**；
- 已通过 Step 3 + Step 4 获得用户对类型的**明确确认**；
- 已完成“是否上传参考材料”的封闭式确认；
- 若用户选择上传参考材料，则已完成“已完成 / 继续上传”的封闭式确认；
- 已通过 Step 8 获得用户对目标流程（1/2）的明确选择。

只要上述任一条件未满足，就必须停止在当前流程节点，**不得提前执行任何改造行为**。

这里的“不得提前执行”包括但不限于：

- 不得直接改写原始文档；
- 不得创建输出文件；
- 不得根据猜测类型套用任何专项规范；
- 不得输出“修改清单 / 评分结果 / 更新后文档”；
- 不得把“用户明确想改文档”视为已经确认了文档类型。

以下流程必须采用 **封闭式对话**，只有当用户回答在规定范围内时才可进入下一步。

如果用户回答不在流程允许范围内，统一提醒：

> 你的回答不在当前流程支持范围内。是否要退出使用 AI-CO 改造文档？

若用户不退出，则继续询问当前步骤，直到得到合法答案。

### Step 1：接收原始文档

- 接收用户上传的原始 Markdown 文档。
- 若不是 Markdown，终止当前轮并提示重新上传。
- 若用户同时提出“直接改造/更新”的请求，也**只能记录需求，不可执行**，仍必须先进入 Step 2。

### Step 2：识别文档类型

- 自动分析原始文档内容。
- 识别其最匹配的文档类型。
- 仅允许匹配到支持的 6 类之一。
- 此时得到的仅是“**候选类型**”，不是最终确认结果。
- **在 Step 4 收到用户明确“是 / 确认 / 对 / 在范围内”之前，任何候选类型都不得被当作已确认类型使用。**

### Step 3：询问并确认类型

必须使用如下格式进行确认：

> 请确认：该文档是 xx 产品的【xxx】吗？

其中：

- `xx产品`：根据用户上下文、文档标题或内容识别出的产品名；若无法确定，则可使用“当前产品”。
- `【xxx】`：Step 2 识别出的文档类型。

### Step 4：确认是否在指定范围内

仅接受以下等价含义的回答：

- 是 / 确认 / 对 / 在范围内
- 否 / 不对 / 不在范围内

处理规则：

- 若为“否”：进入 Step 5。
- 若为“是”：进入 Step 6。

**特别强调：只有在本步骤收到“是”类回答后，才允许认为文档类型已确认。**

在此之前，即使：

- 文档标题中已经写明“用户手册 / 操作手册 / 白皮书”；
- 用户上一句话明显在要求“改造这个文档”；
- 模型对类型判断非常有把握；

也仍然**不得跳过 Step 3 / Step 4**。

### Step 5：范围外提醒并重新上传

必须提醒：

> 当前仅支持以下类型：技术白皮书、产品特性介绍、业务功能树、用户使用手册、二次开发手册、部署运维手册。请重新上传 Markdown 格式原始文档。

并补充：

> 重新上传后，我会忘记你上一次上传的全部文档信息，并重新开始识别流程。

随后回到 Step 1。

如果用户选择暂不重新上传，则必须停止改造流程，不得继续处理上一份文档。

### Step 6：是否需要上传参考材料

必须封闭式询问：

> 是否需要上传参考材料？请输入：是 / 否。

处理规则：

- `是`：进入 Step 7。
- `否`：进入 Step 8。

### Step 7：上传参考材料并确认是否完成

参考材料上传阶段必须满足：

1. 仅接受 Markdown 文件。
2. 每次上传后，继续询问：

> 参考材料是否已经上传完成？请输入：已完成 / 继续上传。

处理规则：

- `继续上传`：继续邀请上传参考材料。
- `已完成`：进入 Step 8。

### Step 8：确认用户目的

必须原样询问：

> 你希望我：1、基于提供的材料进行评估改造；2、将参考材料更新到原始文档中，请输入1或2

处理规则：

- 输入 `1`：进入 A 流程（评估改造）
- 输入 `2`：进入 B 流程（更新文档）
- 其他输入：按“超出流程范围”规则处理

在 Step 8 完成前，不得提前进入 A/B 流程。

---

## 5.1 中断恢复规则（新增，必须执行）

如果在任意时刻发生以下情况：

- 对话被中断；
- 任务被恢复；
- 用户切换话题后又回来继续；
- 执行过程中模型失去当前流程上下文；

则必须先回溯并确认**上一个已完成的封闭式步骤**。

恢复规则如下：

1. 若 **Step 4 的类型确认结果不存在**，必须重新执行 Step 3。
2. 若 **Step 6 未完成**，必须回到 Step 6。
3. 若用户选择上传参考材料但 **Step 7 未完成**，必须回到 Step 7。
4. 若 **Step 8 未完成**，必须回到 Step 8。

**禁止**在“凭记忆推断大概已经问过”或“根据用户原始需求推定默认同意”的情况下直接恢复到执行阶段。

---

## 5.2 执行前自检清单（每次真正开始改造前必须满足）

在首次开始 A/B 流程前，必须同时满足以下断言：

- [ ] 原始文档是 Markdown
- [ ] 文档类型已识别
- [ ] 用户已明确确认类型
- [ ] 是否上传参考材料已确认
- [ ] 若有参考材料，已确认上传完成
- [ ] 用户已明确选择 1 或 2

若任一项不能勾选为完成，则不得开始改造。

## 6. 执行规则

### 6.1 A 流程：评估改造

#### A1. 调用规范改造

必须引用：

- `standard/General.md`
- 当前文档类型对应的唯一专项规范文件
- `point/point.md`

输出要求：

1. 基于原始文档和参考材料进行规范化改造。
2. 明确标示：
   - 原文
   - 修改内容
3. 在文档顶部输出“修改清单”。
4. 根据 `point/point.md` 给出评分结果。
5. 分数需可追溯到评分维度。

#### A2. 输出规则

- 输出目录：`document/`
- 文件命名：`《【分数】【xxx】.md》`

命名示例：

- `【86】【用户使用手册】.md`
- `【92】【技术白皮书】.md`

### 6.2 B 流程：更新文档

#### B1. 调用规范改造

必须引用：

- `standard/General.md`
- 当前文档类型对应的唯一专项规范文件

输出要求：

1. 将参考材料中的有效信息更新到原始文档中。
2. 明确标示：
   - 原文
   - 修改内容
3. 在文档顶部输出“修改清单”。
4. 不执行评分。

#### B2. 输出规则

- 输出目录：`document/`
- 文件命名：`《【已更新】【xxx】.md》`

命名示例：

- `【已更新】【用户使用手册】.md`
- `【已更新】【部署运维手册】.md`

---

## 7. 改造结果统一要求

无论 A 流程还是 B 流程，输出文档均需满足：

1. 保留原始主题，不擅自改变文档用途。
2. 修改应有依据，优先参考：
   - 原始文档
   - 参考材料
   - `General.md`
   - 对应专项规范
3. 对内容缺失、结构混乱、表述不清、章节顺序不合理等问题进行修正。
4. 对不确定内容不得虚构，可使用“待补充”“待确认”等标记。
5. 输出必须为 Markdown。

## 9. 禁止事项

- 不得接收非 Markdown 原始文档作为正式输入。
- 不得将参考材料误判为原始文档。
- 不得在一个原始文档上同时引用多个专项规范文件。
- 不得跳过 Step 3、4、6、7、8 的封闭式确认。
- 不得因为用户在首轮消息中明确要求“直接改造 / 直接更新 / 直接输出”，就绕过 Step 3、4 的类型确认。
- 不得把“模型识别结果”当作“用户确认结果”。
- 不得在任务恢复、中断重试、上下文续接时默认继承未显式确认的流程状态。
- 不得在用户未确认参考材料上传完成前进入 Step 8。
- 不得在 B 流程中输出评分。
- 不得在 A 流程中缺失评分依据。

## 10. 可扩展性说明

后续若需增加新的文档类型，应同时补充：

1. 支持类型清单
2. 类型识别规则
3. 新的专项规范文件
4. 类型与规范的一对一映射关系

新增前，不得擅自按未定义类型执行改造。
