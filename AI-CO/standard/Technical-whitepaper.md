# Technical-whitepaper 技术白皮书专项规范模板

> 说明：本文件仅适用于“技术白皮书”类型文档，且必须与 `General.md` 一起使用。

---

## 1. 基础信息

- 规范名称：技术白皮书专项规范
- 适用文档类型：技术白皮书
- 强制绑定：`standard/Technical-whitepaper.md`
- 更新方式：持续维护
- 当前版本：v0.1

---

## 2. 该类型文档的改造目标

请在此处补充技术白皮书的目标，例如：

- 突出技术架构与设计理念
- 提升技术方案描述的完整性与专业性
- 明确系统边界、适用场景、能力范围
- 增强技术路线、优势、兼容性说明

---

## 3. 推荐章节结构

可参考以下结构模板：

1. 文档概述
2. 建设背景 / 编写目的
3. 产品/系统定位
4. 总体架构
5. 核心能力说明
6. 关键技术实现
7. 安全性 / 稳定性 / 扩展性设计
8. 适用场景
9. 部署或集成概览
10. 限制与边界
11. 附录

---

## 4. 重点检查项

| 检查项 | 是否必需 | 检查说明 | 修改建议 |
|---|---|---|---|
| 技术背景说明 | 是 | 是否说明建设背景、目标问题 | 缺失则补充 |
| 架构描述 | 是 | 是否有清晰的分层/模块/组件说明 | 补图示说明或文本结构化 |
| 核心能力 | 是 | 是否说明核心特性和技术亮点 | 提炼能力清单 |
| 适用场景 | 是 | 是否说明典型应用场景 | 新增场景章节 |
| 边界限制 | 是 | 是否说明不适用范围 | 补充限制 |
| 术语专业性 | 是 | 用词是否专业、准确 | 统一术语 |

---

## 5. 表达风格要求

- 语言专业、客观、克制
- 避免口语化营销语言过多干扰技术表述
- 技术结论需可解释、可追溯

---

## 6. 常见改造方向

- 将零散描述整理为架构化内容
- 补充模块关系说明
- 增加能力与价值之间的逻辑关联
- 强化非功能特性描述（安全、可靠、性能、扩展）
